# 当前代码地图

> 状态：现状记录  
> 更新原则：目录或模块边界发生变化时同步更新；不要在其他设计文档复制服务数量。

## 仓库事实

`server/go.work` 当前包含共享模块以及 game、gateway、config、persist、world、combat、economy、social、operation、inventory、task、match、crossserver 等模块。

这些目录处于不同成熟度：gateway 与 shared 相对完整；部分新增模块主要是领域骨架和表定义。目录存在不代表已完成，也不代表目标部署必须一目录一进程。

## 现有目录到目标上下文的映射

| 现有目录 | 目标归属 | 处理意见 |
|---|---|---|
| `server/shared` | 通用内核 | 保留；继续控制共享内容，避免变成通用杂物箱 |
| `server/gateway` | Identity + 接入层 | 保留；后续拆清鉴权领域与传输适配边界 |
| `server/world` | World | 保留 |
| `server/combat` | Combat | 保留 |
| `server/economy`、`server/inventory` | Economy | 先逻辑协作，是否合并模块由切片调用关系决定 |
| `server/game` | Growth | 模块化单体中的玩家、建筑、训练与单位名册实现；不是新增独立微服务 |
| player/building/training/technology proto | Growth 契约 | player/building/training已有首个领域实现，协议适配与technology仍待后续切片补齐 |
| `server/social` | Social | 后置增强 |
| `server/operation`、`server/config` | LiveOps / control | 保留；明确运行面与管理面 |
| `server/persist` | 数据运维能力 | 不作为所有数据访问的中心服务；各上下文仍拥有仓储 |
| `server/task` | 游戏规则组合或后置模块 | 重新评估是否需要独立上下文，避免与规则引擎重复 |
| `server/match` | Match | 首个闭环后置 |
| `server/crossserver` | CrossServer | 首个闭环后置 |

## 已确认的可复用资产

- 配置版本与热更相关基础能力；
- 强类型游戏包manifest、内容配置编译与双游戏包契约验证；
- 公式解析与确定性随机；
- 规则动作注册表；
- 战斗快照与配置版本绑定；
- DDD 四层目录骨架；
- Protobuf 契约和统一表名定义；
- 静态扫描、依赖检查与集成测试框架。

上述能力仍需由真实垂直切片证明能够协同运行。

## 当前主要差距

1. `gamepacks/insect-world` 已接入Growth只读目录，能够驱动创建玩家、建造建筑和训练单位；
2. Growth当前使用并发安全内存适配器验证边界，尚未接入MySQL、Economy正式资源协议和Gateway注册事件；
3. 多个模块只有骨架，尚未形成创建玩家到战斗结算的连续链路；
4. 默认部署单元、上下文间事务和数据所有权尚未被端到端测试证明；
5. 部分历史规格任务已被代码实现或被新边界否决，需要按需核销而非整体继续执行。

## 演进原则

- 先补闭环，不做全仓目录重构；
- 新代码按目标上下文落位，旧代码在被需求触及时渐进迁移；
- 每次迁移必须保持测试通过，并在 ADR 或任务说明中记录旧新映射；
- 未进入首个闭环的模块不继续扩展功能，只修复阻塞构建和契约一致性的问题。
