## 二、服务器架构设计

### 2.1 服务拆分

```
【核心服务】
  1. 网关服务 (Gateway Service)
     - 负责客户端连接管理
     - 消息路由和转发
     - 协议转换（WebSocket/HTTP）
     - 会话管理
  
  2. 游戏服务 (Game Service)
     - 地图管理
     - 军队移动计算
     - 地块占领逻辑
     - 资源产出计算
  
  3. 战斗服务 (Combat Service)
     - 实时战斗演算
     - 伤害计算
     - 战损统计
     - 战斗回放生成
  
  4. 社交服务 (Social Service)
     - 联盟管理
     - 聊天系统
     - 好友系统
     - 外交系统
  
  5. 经济服务 (Economy Service)
     - 资源管理
     - 贸易系统
     - 商店系统
     - 付费处理
  
  6. 数据服务 (Data Service)
     - 玩家数据持久化
     - 地图数据持久化
     - 战斗数据持久化
     - 社交数据持久化
  
  7. 匹配服务 (Matchmaking Service)
     - 赛季匹配
     - 段位计算
     - 对手匹配
  
  8. 事件服务 (Event Service)
     - 天气事件触发
     - 人类活动事件触发
     - 天灾事件触发
     - 事件效果计算
```

### 2.2 服务通信

```
【内部通信】
  - gRPC：服务间调用
  - RabbitMQ/Kafka：消息队列
  - Redis Pub/Sub：实时通知
  
【通信协议】
  - 客户端→服务器：WebSocket（二进制协议）
  - 服务器→客户端：WebSocket（二进制协议）
  - 服务间：gRPC（Protobuf）
```

## 三、实时同步机制

### 3.1 状态同步

```
【同步策略】
  - 关键状态：服务器权威，客户端预测
  - 非关键状态：客户端自治，服务器校验
  
【同步频率】
  - 军队位置：每秒1次
  - 战斗状态：每秒2次
  - 资源变化：每10秒1次
  - 地块控制：实时同步
```

### 3.2 预测与校正

```
【客户端预测】
  - 军队移动：客户端预测下一帧位置
  - 战斗伤害：客户端预测伤害结果
  - 资源产出：客户端预测产出数量
  
【服务器校正】
  - 服务器权威计算
  - 客户端收到校正后修正
  - 平滑过渡避免跳跃
```

### 3.3 延迟处理

```
【网络延迟】
  - 目标延迟：< 100ms
  - 最大延迟：500ms
  - 延迟补偿：客户端预测+服务器校正
  
【延迟影响】
  - 军队移动：预测移动，延迟<200ms时无感知
  - 战斗计算：服务器权威，延迟影响较小
  - 资源产出：后台计算，无实时性要求
```

## 四、地图系统设计

### 4.1 地图分块

```
【分块策略】
  - 地图分为多个区块（Chunk）
  - 每个区块10×10格
  - 客户端只加载视野内区块
  - 区块动态加载/卸载
  
【区块管理】
  - 中心区块：高优先级加载
  - 边缘区块：低优先级加载
  - 远离区块：卸载释放内存
```

### 4.2 地块数据

```
【地块数据结构】
  struct Tile {
    int x, y;                      // 坐标
    int type;                      // 地块类型
    int owner;                     // 控制者（0=无人，>0=玩家ID）
    int reserve;                   // 驻军ID
    int resource;                  // 资源产出
    int level;                     // 地块等级
    int event;                     // 当前事件
    long lastUpdate;               // 最后更新时间
  }
  
【地块状态】
  - 控制状态：无人/己方/敌方/联盟
  - 资源状态：产出中/枯竭/事件影响
  - 军事状态：驻军/战斗/被围
```

## 五、军队移动系统

### 5.1 移动计算

```
【服务器计算】
  - 每1秒计算一次军队位置
  - 考虑地形/天气/事件影响
  - 检测碰撞/拦截
  - 同步到所有客户端
  
【客户端渲染】
  - 每0.5秒渲染一次
  - 插值平滑移动
  - 预测下一帧位置
```

### 5.2 路径规划

```
【路径算法】
  - A*算法：寻找最短路径
  - 动态避障：避开敌方军队
  - 地形权重：优先选择快速地形
  
【路径缓存】
  - 常用路径缓存
  - 避免重复计算
  - 实时更新路径
```

## 六、战斗系统

### 6.1 战斗演算

```
【服务器演算】
  - 每10秒计算一次伤害
  - 考虑兵种克制/地形/天气
  - 计算战损
  - 生成战斗日志
  
【客户端渲染】
  - 实时显示伤害数字
  - 播放战斗动画
  - 显示战损统计
```

### 6.2 战斗回放

```
【回放生成】
  - 服务器记录战斗日志
  - 包含：时间/位置/伤害/战损
  - 生成回放数据
  
【回放播放】
  - 客户端播放回放
  - 支持快进/暂停/倒退
  - 可切换视角
```

## 七、经济系统

### 7.1 资源计算

```
【离线计算】
  - 玩家离线时，服务器后台计算资源产出
  - 计算精度：每分钟
  - 上线时同步累积资源
  
【在线计算】
  - 实时计算资源产出
  - 每10秒更新一次
  - 采集队实时计算
```

### 7.2 贸易系统

```
【贸易计算】
  - 服务器计算贸易路线
  - 考虑距离/税率/护送
  - 实时同步贸易状态
  
【贸易安全】
  - 贸易队可被伏击
  - 伏击计算在服务器
  - 结果实时同步
```

## 九、事件系统

### 9.1 事件触发

```
【触发机制】
  - 定时器触发：天气/人类活动
  - 条件触发：玩家行为/战斗结果
  - 随机触发：天灾事件
  
【事件计算】
  - 服务器计算事件影响
  - 同步到相关客户端
  - 记录事件日志
```

### 9.2 事件效果

```
【效果计算】
  - 伤害效果：计算单位伤害
  - 状态效果：添加/移除状态
  - 地形效果：改变地块状态
  
【效果同步】
  - 实时同步到所有受影响的客户端
  - 显示事件UI
  - 播放事件动画
```

## 十一、架构设计总结

| 层级 | 核心组件 | 技术选型 | 关键设计 |
|------|----------|----------|----------|
| 客户端 | 渲染/输入/UI | Unity/UE | 预测渲染+插值平滑 |

| 服务 | 游戏/战斗/社交 | gRPC/消息队列 | 服务拆分+负载均衡 |
