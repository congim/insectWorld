# ADR-006 Outbox租约投递与业务幂等消费

> 状态：已接受  
> 日期：2026-08-13

## 背景

Gateway注册已经能把账号与`auth.player_registered`事件写入同一事务，但没有运行时负责领取、发布、失败重试。简单轮询存在多实例重复领取、消费者错误被吞掉、进程中断后永久卡住等风险。

## 决策

采用MySQL Outbox租约领取与至少一次投递：

- 轮询实例用`SELECT ... FOR UPDATE SKIP LOCKED`领取批次；
- 每个发布器必须声明已注册消费者的事件类型白名单，只领取自己负责的事件；
- 领取后状态变为投递中，`available_time`表示租约到期时间；
- 进程退出后，其他实例可以重新领取过期租约；
- 消费者任一失败时发布返回错误，Outbox记录失败摘要并指数退避；
- 全部同步消费者成功后才标记已发布；
- 不承诺恰好一次投递，消费者必须使用事件ID作为业务幂等键；
- Growth以玩家档案`command_id`唯一键作为注册事件消费凭据，重复投递不会重复创建玩家或发放资源。
- 发布器暴露累计领取、成功、失败、当前投递中数量和最近轮询耗时，告警阈值等产生压测基线后再冻结。

## 取舍

选择至少一次而非分布式恰好一次，因为后者需要消息事务与各业务数据库组成不可接受的全局事务。租约可能在处理时间超过配置值时造成并发重复投递，因此租约必须大于正常处理上界，业务幂等仍是最终安全边界。

当前内存事件总线用于单进程装配与自动化测试；跨进程传输适配器可以后续替换，但不得改变Outbox状态机和消费者幂等契约。

## 验证

- 多实例领取使用行锁和跳锁；
- 消费失败进入指数退避；
- 投递中实例崩溃后可按租约恢复；
- 注册事件重复发布仍只产生一份玩家档案和初始资源。
