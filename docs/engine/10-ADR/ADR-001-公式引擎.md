# ADR-001 公式引擎升级：AST表达式引擎 + 内置函数库 + 种子化确定性随机

> **状态**：已接受（Accepted）
> **日期**：2026-08-11
> **决策者**：程基岩（engineering-lead）
> **关联**：《通用SLG服务端开发计划》P1-E1；《通用SLG框架设计书》3.5 伤害公式契约、3.6 经济契约、3.8 规则条件表达式；`docs/engine/02-技术架构/03-规则系统.md`；`docs/game/13_数值平衡白皮书.md`
> **依赖**：无（P1 第一个 Epic，最先启动）
> **被依赖**：E2 行为注册表（`execute_formula` 动作引用公式引擎）、E3 切片主链路（战斗伤害/经济产出/战斗回放）、E14 存量功能

---

## 一、背景与问题

### 1.1 现状

设计书 3.5.1 伤害公式契约声明公式引擎支持"四则运算 + 变量替换"（变量 `atk/def/counter/terrain_mod/buff_mod/random`）。经评审核验，现状存在以下缺陷：

| 缺陷 | 表现 | 后果 |
|------|------|------|
| 契约文本不可执行 | 契约虽列举 `min()/max()/floor()/ceil()/random(a,b)`，但未定义语法规则、运算符优先级、函数签名与求值语义，无法形成可执行规格 | 实现层面实际只有四则运算+变量替换，函数名仅是文档摆设 |
| 随机无确定性 | `random` 无种子、无随机源注入，无回放契约 | 战斗回放无法重放同一结果，战报可信度与对账能力缺失 |
| 无条件表达式 | 无 `if`/比较/逻辑运算 | 无法表达"首击暴击×2.0（螳螂族）""攻城加成×1.5（泰坦甲虫）""伏击加成×1.5（森林地形）"等条件公式 |
| 函数库残缺 | 无 `clamp/abs/round` | 无法表达钳制与取整语义（资源上限、属性钳制） |
| 无编译期校验 | 无"校验失败拒绝加载"机制 | 公式写错只能运行时才发现，热更风险高 |

### 1.2 评审结论

《通用SLG框架设计评审报告》**高风险#1：公式表达力不足**。若不升级，将导致框架的"配置化承诺"落空——策划无法用配置实现真实战斗公式，被迫回到硬编码，破坏"换皮=换肉，骨头不动"。

《通用SLG服务端开发计划》将公式引擎升级列为 **P1-E1（最先启动）**：用真实昆虫公式验证表达力，**失败则终止"配置化承诺"，改走扩展点方案**。本 ADR 即该预研的架构决策产出。

### 1.3 表达力验证集（必须全部可表达、可求值）

从《13_数值平衡白皮书》抽取的必选公式：

```
#1  伤害 = 攻击 × (1 - 防御/100) × 克制系数 × random(0.9, 1.1)
#2  血量 = 类型基础 × (1 + 等级 × 0.1) × (1 + 种族防御修正)
#3  攻击 = 类型基础 × (1 + 等级 × 0.1) × (1 + 种族攻击修正)
#4  升级成本 = 基础成本 × (1 + 等级 × 0.5)
#5  战斗力 = Σ(单位血量 × 攻击 × 克制系数) / 100
#6  首击伤害 = if(种族 == 螳螂, 伤害 × 2.0, 伤害)        （条件公式）
#7  保留量 = min(原值 × keep_ratio, keep_amount)          （赛季遗产）
#8  基础伤害 = max(atk × counter - def × terrain_mod, 1) （设计书默认伤害公式）
```

## 二、决策

**采用：AST表达式引擎 + 内置函数库 + 种子化确定性随机（RandSource 注入）。**

三个组成部分：

1. **表达式语法**：词法分析 + 递归下降解析 → AST；
2. **内置函数库**：`min/max/floor/ceil/round/random/clamp/abs/if` + 比较/逻辑运算符；
3. **种子化随机**：`RandSource` 接口注入，内置确定性 PRNG 实现；**同种子同结果**；战斗以"战斗ID + config_version"派生种子，保证回放一致。

执行模型：**编译期解析+校验生成 AST，运行期直接 AST 树遍历求值（不做字节码 VM）**，理由见 3.4。

## 三、设计要点

### 3.1 表达式语法

EBNF 规格：

```
expression  := or_expr
or_expr     := and_expr ( "or" and_expr )*
and_expr    := cmp_expr ( "and" cmp_expr )*
cmp_expr    := add_expr ( ("==" | "!=" | ">" | ">=" | "<" | "<=") add_expr )?
add_expr    := mul_expr ( ("+" | "-") mul_expr )*
mul_expr    := unary_expr ( ("*" | "/") unary_expr )*
unary_expr  := ("-" | "not") unary_expr | primary
primary     := number | variable | func_call | "(" expression ")"
func_call   := identifier "(" [expression ("," expression)*] ")"
```

- **运算符优先级（高→低）**：`()` > 一元 `-` / `not` > `*` `/` > `+` `-` > 比较（`== != > >= < <=`）> `and` > `or`
- **变量引用**：简单标识符（字母开头，含字母数字下划线），对应求值期扁平变量表（如 `atk/def/counter/level/base`）。层级上下文（如 `attacker.atk`）由调用方拍平为前缀变量（如 `attacker_atk`），保持引擎语法简单。
- **函数调用**：`函数名(参数[, 参数...])`，参数为表达式，支持嵌套。
- **字面量**：整数（`123`）、小数（`1.5`）、可带一元负号（`-0.1`）。

### 3.2 内置函数库清单

| 函数 | 签名 | 语义 | 用途示例 |
|------|------|------|----------|
| min | `min(a, b)` | 取较小值 | 赛季遗产保留量 `min(原值×keep_ratio, keep_amount)` |
| max | `max(a, b)` | 取较大值 | 伤害下限 `max(atk×counter-def, 1)` |
| floor | `floor(x)` | 向下取整 | 离散业务量（兵力、资源量）结算 |
| ceil | `ceil(x)` | 向上取整 | 需求/消耗向上取整 |
| round | `round(x)` | 四舍五入取整 | 展示/结算精度处理 |
| random | `random()` → `[0,1)`；`random(n)` → `[0,n)`；`random(a,b)` → `[a,b]` | 均匀随机，从注入的 RandSource 取值 | 伤害波动 `random(0.9,1.1)`、掉落判定 |
| clamp | `clamp(x, lo, hi)` | 钳制到 `[lo,hi]` | 属性钳制、资源上限 |
| abs | `abs(x)` | 绝对值 | 差值/距离计算 |
| if | `if(cond, t, f)` | 条件选择，`cond` 为比较/逻辑表达式，为真取 `t` 否则取 `f` | 首击暴击 `if(种族==螳螂, 伤害×2, 伤害)` |
| 比较运算符 | `> >= < <= == !=` | 返回 `1.0/0.0` | 配合 `if` 使用 |
| 逻辑运算符 | `and` / `or` / `not` | 返回 `1.0/0.0` | 配合 `if` 使用 |

**预留（本期不实现，接口可扩展）**：`%` 取模（周期性判定）、`pow`、`sqrt`。

### 3.3 种子化随机方案

- **RandSource 接口**：求值期显式注入，公式引擎**不持有全局随机状态**，保证无隐式状态泄漏、可并发求值。
- **内置确定性实现**：固定算法（PCG32 风格，算法代码内冻结），**不依赖 `math/rand` 的版本行为**——`math/rand` 的生成算法在 Go 版本间可能漂移，会破坏跨版本回放一致性；冻结算法保证跨进程、跨 Go 版本同种子同序列。
- **默认随机源派生**：
  - 战斗结算创建**战斗级 RandSource**，种子 = hash(combatID, config_version, round)，round 为战斗轮次；同一次战斗重放时用相同种子重建，逐轮结果完全一致（E3 验证回放一致性）；
  - 非战斗场景（经济产出等）按 playerID/实例ID 派生种子，保证可复现；无特别要求时注入默认实现。
- **随机消费边界**：随机只在公式内消费；战报记录种子，事后可重放对账。

### 3.4 编译流程与执行模型

```
formulas.json
   ↓ config模块读取原始JSON
Parse：词法分析 → 递归下降语法分析 → AST
   ↓
Validate：语法错误 / 函数是否存在 / 参数个数 / 变量是否在允许列表 / 嵌套深度 ≤ maxDepth
   ↓ 任一失败 → 拒绝加载，输出 文件+公式ID+错误信息+修复建议
Compile → *Formula{source, root}
   ↓ Register(formulaID, formula) 存入引擎缓存，重复注册报错
运行时 Eval(formula, vars, rand) → AST树遍历求值 → float64
```

**执行模型选择：直接 AST 树遍历，不做字节码 VM。** 理由：

| 维度 | 说明 |
|------|------|
| 规模 | formulas.json 通常几十~几百条公式，单条求值为微秒级，战斗 tick 频率下不构成热点（规范4.7 避免过早优化） |
| 可调试性 | AST 直接求值错误可定位到具体节点，便于定位配置错误 |
| 实现成本 | 字节码 VM（或编译为闭包）显著增加实现与维护成本，P1 是表达力验证阶段，不承担此复杂度 |
| 优化路径 | 若 E4 剖析证明热点，在同一 `Formula/FormulaEngine` 接口后替换为编译求值，不预先实现（YAGNI） |

### 3.5 与配置加载的衔接

- `formulas.json` 经 config 模块 `ExtPointDamageFormulas`（= `"formulas.damage_formulas"`，见 `extension_registry.go`）加载。
- 配置加载阶段（启动时）调用公式引擎：遍历 formulas **全量 Parse+Validate**，任一公式非法 → **配置加载失败，服务拒绝启动**（对齐设计书"配置包校验流程"自定义校验步骤）。
- 校验通过后 `Register` 到引擎缓存；热更时重新 Parse，新版本公式非法则**保留旧版本并告警**（与 E3 config_version/熔断机制衔接）。
- 错误报告格式：`formulas.json#basic_damage: 函数 unknown_func 未定义`，附修复建议。

### 3.6 代码示例（Go）

遵循 AGENTS.md：中文注释、导出标识符中文注释、结构体字段行内中文注释、常量就近归属、错误包裹上下文。

```go
// Package formula 通用公式引擎，提供AST表达式解析、内置函数库与种子化确定性随机求值。
// 公式引擎将配置中的公式字符串编译为AST，运行时按输入变量与注入的随机源求值；
// 同一输入与同一随机种子必然产生完全一致的结果（战斗回放一致性依赖此特性）。
package formula

import "fmt"

// maxDefaultDepth 表达式最大嵌套深度默认值，超限拒绝编译，防止恶意/失控配置。
const maxDefaultDepth = 10

// RandSource 确定性随机源接口，由调用方注入，保证同一种子产生同一序列。
// 内置实现采用固定算法（代码内冻结），不依赖math/rand的版本行为，跨进程同种子同结果。
type RandSource interface {
	// Float64 返回[0,1)区间内的伪随机浮点数，供random()函数消费。
	Float64() float64
	// Int63n 返回[0,n)区间内的伪随机整数，n必须大于0，供随机判定类函数消费。
	Int63n(n int64) int64
}

// EvalContext 单次求值的输入上下文，携带变量与随机源。
type EvalContext struct {
	Vars map[string]float64 // 变量表，公式引用的变量在此读取，缺失按0处理并记录Warn
	Rand RandSource         // 随机源，公式含random()时必须注入，缺失时random返回0并记录错误
}

// Formula 编译后的公式，由Parse生成，只读且可并发求值（同一公式多实例共享）。
type Formula struct {
	source string   // 原始公式字符串，用于错误报告与日志
	root   exprNode // AST根节点，编译期生成，运行期只读
}

// FormulaEngine 公式引擎，管理公式编译缓存、内置函数库与校验参数。
type FormulaEngine struct {
	formulas map[string]*Formula // 公式ID到编译后公式的映射，key为formulas.json中的公式ID
	funcs    map[string]function // 函数名到函数实现的映射，New时注册内置函数库
	maxDepth int                 // 表达式最大嵌套深度，超限拒绝编译
}

// NewFormulaEngine 创建公式引擎实例并注册内置函数库。
func NewFormulaEngine() *FormulaEngine {
	return &FormulaEngine{
		formulas: make(map[string]*Formula),
		funcs:    registerBuiltinFuncs(),
		maxDepth: maxDefaultDepth,
	}
}

// Parse 解析并编译单个公式表达式，语法/函数/变量/深度校验任一失败返回错误。
// 配置加载阶段对全量公式调用Parse，任一失败即拒绝加载（设计书配置校验流程）。
func (e *FormulaEngine) Parse(source string) (*Formula, error) {
	return parse(source, e.funcs, e.maxDepth)
}

// Register 注册公式ID到编译后公式的映射，重复注册返回错误，避免覆盖已注册公式。
func (e *FormulaEngine) Register(formulaID string, f *Formula) error {
	if formulaID == "" {
		return fmt.Errorf("公式ID不能为空")
	}
	if f == nil {
		return fmt.Errorf("公式不能为空")
	}
	if _, exists := e.formulas[formulaID]; exists {
		return fmt.Errorf("公式 %s 重复注册，禁止覆盖", formulaID)
	}
	e.formulas[formulaID] = f
	return nil
}

// Eval 按变量与随机源求值公式，返回float64；同一Vars+Rand必然同结果（确定性）。
// 业务离散量（兵力、资源量）由调用方用floor/round转换为int64后落库（AGENTS.md规范8）。
func (e *FormulaEngine) Eval(f *Formula, vars map[string]float64, rand RandSource) (float64, error) {
	return evalNode(f.root, EvalContext{Vars: vars, Rand: rand})
}

// EvalByID 按公式ID求值，公式未注册时返回错误。
func (e *FormulaEngine) EvalByID(formulaID string, vars map[string]float64, rand RandSource) (float64, error) {
	f, exists := e.formulas[formulaID]
	if !exists {
		return 0, fmt.Errorf("公式 %s 未注册", formulaID)
	}
	return e.Eval(f, vars, rand)
}
```

### 3.7 落地拆解（E1 的 4 个 Story 建议）

| Story | 内容 | 验收 |
|-------|------|------|
| E1-S1 | 词法+递归下降语法解析器 → AST（优先级/一元负号/函数调用/括号/比较/逻辑） | 语法用例全覆盖，非法输入报错定位到字符位置 |
| E1-S2 | 内置函数库 + AST 树遍历求值器（含 if/比较/逻辑） | 验证集 8 条真实公式（1.3 节）全部可编译可求值，结果与手工计算一致 |
| E1-S3 | RandSource 接口 + 确定性 PRNG 实现 + 种子派生工具 | 同种子同结果单测；随机序列与 math/rand 行为解耦（冻结算法） |
| E1-S4 | 配置加载衔接（formulas.json 全量编译、失败拒绝加载）+ E3 战斗种子接入 | 非法公式拒绝加载并输出文件+公式ID+原因+修复建议 |

## 四、备选方案对比

| 方案 | 说明 | 评估 | 结论 |
|------|------|------|------|
| A. 字符串替换 + 扩展运算符表 | 现状升级：仅扩展"运算符符号"支持 min 等特殊 token | 无函数嵌套、无 if 条件、无优先级解析，表达力仍不足；退化为"字符串魔法"，不可调试 | 否决 |
| B. 引入第三方表达式库（govaluate 等） | 成熟库，自带 AST/函数机制 | 需评估许可/稳定性/体积；确定性随机需额外封装；govaluate 对条件/嵌套函数/布尔表达式支持一般；通用引擎引入第三方依赖需统一评估 | 暂缓，P1 自研验证表达力；E4 后如自研成本超预期再评估（记入 ADR 备选，不预选） |
| C. Lua 脚本 | 表达力最强 | 引入 VM+绑定层，部署/安全/性能复杂度高；"配置中放代码逻辑"违反 AGENTS.md 规范4.4 禁止过度配置化 | 否决 |
| D. AST + 函数库 + 种子随机（选定） | 见第三章 | 表达力覆盖验证集；确定性随机内建；零第三方依赖；实现量可控（约 500-800 行，E1 估算 6 人日） | ✅ 选定 |

## 五、影响范围

| 系统 | 影响 |
|------|------|
| 战斗系统 | 伤害公式执行器从"四则+变量替换"改为调用公式引擎 `Eval`，注入战斗级 RandSource；战斗快照记录种子（E3 config_version 绑定） |
| 经济系统 | 产出/消耗/采集/贸易/饥荒溢出公式改走公式引擎；`random` 按实例种子保证可复现 |
| 规则系统 | 条件表达式契约（设计书 3.8.3）与公式引擎共享比较/逻辑语法子集；E2 的 `execute_formula` 动作直接调用公式引擎 |
| 配置加载 | `formulas.json` 增加编译期校验，失败拒绝加载；热更失败保留旧版本并告警 |
| 文档 | 设计书 3.5.1 契约需补充语法规格与函数库清单，以本 ADR 为权威规格 |

**知识缺口标记**：若验证集出现超出函数库能力、且无法用现有函数组合表达的必选公式，按开发计划风险#1 缓解动作处理——回写本 ADR 并触发降级评审（改扩展点方案）。当前函数库已覆盖白皮书全部公式形态，暂未发现缺口。

## 六、验收标准（对齐开发计划 E1）

- [ ] 验证集 8 条真实昆虫公式（1.3 节）全部可编译、可求值，结果与手工计算一致；
- [ ] 同公式 + 同变量 + 同种子两次求值结果**完全一致**（random 回放一致）；
- [ ] 战斗回放：记录种子后按轮次重放，伤害序列一致（E3 验证）；
- [ ] `formulas.json` 含非法公式（未定义函数/语法错误/超深度）时**服务拒绝加载**，错误报告含文件+公式ID+原因+修复建议；
- [ ] 单测覆盖率：解析器/函数库/随机 ≥ 80%（application/domain 层要求）；
- [ ] 知识缺口闭环：若发现无法表达的必选公式，回写本 ADR 并触发降级评审（不静默降级）。
