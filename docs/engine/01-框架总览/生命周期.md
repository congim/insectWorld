# 框架运行时生命周期

## 1.5 框架运行时生命周期

```
┌─────────────────────────────────────────────────────────┐
│                    框架生命周期                           │
└─────────────────────────────────────────────────────────┘

Phase 1: 初始化（启动时一次性）
  ├─ 1.1 加载配置文件（配置加载核心模块）
  │    └─ 失败 → 拒绝启动，报告配置错误
  ├─ 1.2 校验配置（配置加载核心模块）
  │    └─ 失败 → 拒绝启动，报告校验错误
  ├─ 1.3 编译公式（配置加载核心模块）
  │    └─ 失败 → 拒绝启动，报告公式错误
  ├─ 1.4 初始化事件总线（事件总线核心模块）
  ├─ 1.5 按依赖顺序初始化核心模块（拓扑排序）
  │    ├─ L0: 实体 → 事件总线
  │    ├─ L1: 地图 → Buff → 配置加载
  │    ├─ L2: 移动 → 经济
  │    ├─ L3: 战斗 → 规则
  │    ├─ L4: 联盟 → 赛季 → 事件
  │    └─ L5: 网络同步 → 持久化
  └─ 1.6 开始接受客户端连接

Phase 2: 运行（主循环）
  ├─ tick频率：默认10 tick/s（可配，建议5-20）
  ├─ 每tick超时阈值：默认80ms（超过则WARN并跳过非关键步骤）
  └─ 每tick:
       ├─ 收网络消息 → 校验 → 入队
       ├─ 按固定顺序更新各核心模块（顺序见Phase 1的L0-L5）
       ├─ 事件总线派发事件
       ├─ 广播状态变更
       └─ 标记脏数据 → 批量持久化（每N tick刷盘一次，默认N=10）

Phase 3: 热更新（运行时）
  ├─ 检测机制：文件系统watch（inotify/fsevent）+ 手动触发API
  ├─ 检测到变更后流程：
  │    ├─ 加载新配置 → 校验
  │    │    └─ 校验失败 → 保留旧配置 → 记录WARN日志 → 发出CONFIG_RELOAD_FAILED事件
  │    ├─ 原子替换配置引用（通过atomic.Pointer或RWMutex切换指针）
  │    ├─ 发出CONFIG_RELOADED事件（携带变更的配置项列表）
  │    └─ 依赖该配置的运行时状态按需刷新（如已生成的实体不回溯，新创建的用新配置）
  └─ 热更粒度：单文件级（一个json一个json地热更，不批量）

Phase 4: 优雅停机
  ├─ 4.1 停止接受新连接
  ├─ 4.2 通知所有客户端"服务器关闭"（设超时30s，超时则强制断开）
  ├─ 4.3 等待当前tick完成（最长等待1个tick周期，超时则强制中断）
  ├─ 4.4 全量持久化（不等定时刷盘，设超时60s）
  ├─ 4.5 按依赖逆序关闭核心模块
  │    ├─ L5逆: 持久化 → 网络同步
  │    ├─ L4逆: 事件 → 赛季 → 联盟
  │    ├─ L3逆: 规则 → 战斗
  │    ├─ L2逆: 经济 → 移动
  │    ├─ L1逆: 配置加载 → Buff → 地图
  │    └─ L0逆: 事件总线 → 实体
  └─ 4.6 进程退出
```
