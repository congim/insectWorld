# 契约冻结草案（proto 契约冻结核查）

> 状态：历史草案。只有已发布并由兼容性测试保护的 proto 才视为冻结契约；现行实现状态见[当前代码地图](../../architecture/当前代码地图.md)。

> **任务**：P2-E7（eng 域）——对 `server/shared/proto/` 现有 9 个 proto 契约包做冻结前核查，验证是否支撑 P3 六根新骨头（玩家档案/建筑升级/采集调度/背包道具/兵种训练/个人科技）的接口需求，产出契约冻结草案。
> **编制**：程基岩（engineering-lead）
> **日期**：2026-08-11
> **依据**：`server/shared/proto/` 9 包（admin/common/combat/config/economy/event/operation/social/world）、《通用SLG框架共性抽离方案_终版》（P0-1~P0-6 六骨头）、《契约表达力缺口对照表》（docs/engine/06-扩展指南/）
> **对齐**：《通用SLG服务端开发计划》E7 验收"契约冻结草案"

---

## 一、核查范围与方法

- **范围**：`server/shared/proto/` 下 9 个 proto 包（以 `.proto` 源文件为准，.pb.go 为生成物不单独核查）。
- **方法**：对每个包枚举已定义 service/rpc 与 message；对 P3 六根骨头逐根拆出三类接口需求（**command** 玩家指令 / **事件** 领域事件 / **查询** 只读查询），逐一比对现有契约，判定 ✅有 / ⚠️部分 / ❌缺。
- **口径**：与《契约表达力缺口对照表》一致——"接口存在且字段/语义可承载"才计 ✅；能组合表达主体但缺关键命令/事件计 ⚠️；无任何契约承载计 ❌。

## 二、现有 9 个 proto 包接口能力清单

### 2.1 common（基础消息，无 service）

| 消息 | 能力 |
|------|------|
| RequestHeader / ResponseHeader | 跨服务请求/响应头：request_id/trace_id/player_id 链路追踪、error_code/error_msg 错误返回 |
| Position | 地图二维整型坐标（int32 x/y） |
| Pagination / PaginationResult | 分页参数与结果 |

> 冻结基石件：全部现有 rpc 均依赖此包，**任何字段编号变更都会破坏全部契约**。

### 2.2 admin（AdminService，运营管理面）

| RPC | 类别 |
|-----|------|
| ReloadConfig / RollbackConfig | 配置热更/回滚 |
| ForceTransitionPhase / ForceResetSeason | 赛季强制推进/重置 |
| ManualTriggerEvent | 事件手动触发 |
| BanPlayer / UnbanPlayer | 玩家封禁/解封 |
| PublishNotice | 公告发布 |

> 全部管理操作带 admin_token 鉴权；**面向运营后台，非玩家面**。

### 2.3 combat（CombatService，查询面）

| RPC | 能力 |
|-----|------|
| GetEntityAttributes | 实体攻/防/血/兵种类型/阵型查询 |
| GetCombatState | 战斗状态/轮次/参战方查询 |
| GetCombatReport | 战报查询（RoundReport/SkillUsage） |

> **纯查询**：无发动战斗/撤退等指挥 command。兵种属性查询可被兵种训练骨头复用。

### 2.4 config（ConfigService，配置管理面）

| RPC | 能力 |
|-----|------|
| SubmitConfigPack | 配置包提交（zip+md5） |
| RollbackConfig | 配置回滚 |
| GetConfigVersionHistory | 版本历史（分页） |

> 配置分发/版本管理面，与玩法接口正交。

### 2.5 economy（EconomyService，查询面）

| RPC | 能力 |
|-----|------|
| GetPlayerResources | 玩家资源查询（ResourceItem：type/amount/capacity/production_rate） |
| CheckSufficient | 资源充足性校验 |
| GetAllianceBonus | 联盟加成查询 |

> **纯查询**：无扣费/发放 command（资源变更走事件 + 规则动作）。采集调度的资源载荷语义可参考 ResourceItem。

### 2.6 event（领域事件 Schema，无 service）

| 消息 | 能力 |
|------|------|
| DomainEvent | 事件基础：event_id/type/timestamp/aggregate_id/publisher/version（**内置版本机制**） |
| TerrainChangedEvent / RegionCreatedEvent / RegionDestroyedEvent | 地图/区域域事件 |
| WelfareDistributedEvent / ProductionCompletedEvent | 联盟福利/生产完成事件 |
| InheritCompletedEvent / RewardDistributedEvent / EventExpiredEvent | 赛季继承/奖励/事件过期 |
| RewardItem | 奖励项（item_type：1=资源 2=道具）——**唯一出现"道具"语义处** |

> 事件主题约定 `world.terrain.changed` 式 `域.聚合.动作`。**覆盖地图/生产/赛季/福利/奖励域；六骨头域（玩家/建筑/采集/背包/训练/科技）零事件**。

### 2.7 operation（OperationService，运营查询面）

| RPC | 能力 |
|-----|------|
| GetCurrentSeason / GetSeasonHistory | 赛季/历史赛季查询 |
| GetRanking | 排行榜查询 |
| TriggerGameEvent | 游戏事件触发 |

> 赛季/排行/事件触发，运营与玩家共用查询面。

### 2.8 social（SocialService，社交查询面）

| RPC | 能力 |
|-----|------|
| GetPlayerInfo | 玩家资料查询（player_id/name/alliance_id/alliance_role/**level**/online） |
| GetDiplomacyStatus | 外交状态查询 |
| CheckAlliancePermission | 联盟权限校验 |
| GetPlayerAllianceTerritory | 联盟领土查询 |

> `GetPlayerInfo` 的 player_id/level 字段语义可被玩家档案骨头复用（只读，缺注册/登录/成长接口）。

### 2.9 world（WorldService，地图/实体查询面）

| RPC | 能力 |
|-----|------|
| GetEntityPosition | 实体坐标 + 移动状态（move_status：静止/移动中/已到达/已阻挡） |
| GetMapSnapshot | 地图快照（CellData：terrain/entity_id/entity_type=3 建筑） |
| CheckPassable / GetTerrainInfo / GetVisionCells | 通行/地形（含 is_buildable）/视野查询 |

> 建筑仅作为地图格子实体类型标注（entity_type=3）；**无建造/升级接口**。移动状态可部分支撑采集"去程/返程"语义。

### 2.10 总体观察（关键结论）

1. 现有 9 包以**查询面 + 运营管理面 + 事件 Schema** 为主，**玩家指令面（command）整体空缺**——没有任何"发起一个玩法行为"的 rpc。
2. 事件包已建立 DomainEvent 基础与版本机制，**新增事件只需继承 base，零破坏**。
3. P3 六骨头需要的 command 与事件**绝大多数不在现有契约中**；可复用面仅为：玩家资料查询（玩家档案）、移动状态/资源载荷（采集调度）、兵种属性（兵种训练）、CellData 建筑标注（建筑升级的实体面）。
4. 因此结论：**六骨头缺口 = P3 立项时新增契约（新包/新服务/新事件），而非修改现有 9 包**。

## 四、契约冻结建议

### 4.1 本期冻结清单（冻结 = 禁止改字段编号/类型/删除，只能追加）

| 包 | 冻结对象 | 冻结版本 |
|----|---------|---------|
| common | 全部 5 消息（RequestHeader/ResponseHeader/Position/Pagination/PaginationResult） | v1 |
| world / economy / combat / social / operation / config / admin | 7 个 service 的全部现有 rpc 与消息 | v1 |
| event | DomainEvent 基础消息（version 机制内置，语义变更升 version） | v1 |

**冻结规则**（proto3 兼容性铁律）：
1. **字段编号不重用**：已发布消息的字段编号永久占用，删字段只留 reserved，新字段从最大编号 +1 追加；
2. **字段类型不可变**：int32↔int64、message↔repeated 均为破坏性变更，一律禁止；
3. **消息只增不改**：已发布消息新增字段向前兼容，语义变更必须新增字段/新消息，不改旧字段语义；
4. **服务只加不改**：新增 rpc 向后兼容，禁止修改既有 rpc 签名；跨服务行为变更走事件版本（event.DomainEvent.version）。

### 4.2 缺口处理原则（P3 立项时新增）

1. **独立命名空间**：六骨头各建独立 proto 包（`insectworld.player` / `building` / `gathering` / `inventory` / `training` / `technology`），**不修改已冻结包**，冻结包零 diff；
2. **command / 事件 / 查询三面齐备**：每根骨头至少提供"发起指令 rpc + 状态查询 rpc + 领域事件"，事件继承 `event.DomainEvent` base（复用已有版本机制），主题命名 `event.<service>.<action>`（如 `event.building.upgraded`）；
3. **配置化优先**：骨头机制（状态机/队列/前置依赖/解锁条件）遵循"配置 Schema（buildings/techs/items/training 配置）+ 机制服务"双轨——proto 只承载机制指令与状态回传，数值/规则/条件留在配置层（对齐 ADR-001/002/003 与 07 配置包总清单），保证换皮零代码；
4. **C 类扩展点不入本期冻结**：表达力对照表识别的题材层扩展点（信息素场 movement_path_markers、随机目的地生成器 movement_teleport_destination_generators、真 3D 距离 map_distance_formula）属 E14/E16 题材扩展期，本期仅**预留命名空间约定**（extensions/<题材>/），不占 proto 冻结号段。

### 4.3 建议新增 proto 消息/服务清单（P3 立项时，完整文件另出）

| 新包 | 服务 | 建议 rpc（command/查询） | 关键消息 | 建议事件 |
|------|------|------------------------|---------|---------|
| **player.proto** `insectworld.player` | PlayerProfileService | RegisterPlayer / LoginPlayer / GetPlayerProfile / UpdateNickname / AddExperience / GetLevelConfig | PlayerProfile（player_id/nickname/level/exp/created_at/avatar） | PlayerRegisteredEvent / PlayerLevelUpEvent / PlayerProfileUpdatedEvent |
| **building.proto** `insectworld.building` | BuildingService | StartBuilding / UpgradeBuilding / GetBuildingList / GetBuildingUpgradeQueue / CancelBuilding / AccelerateBuilding | BuildingState / BuildingUpgradeTask（building_id/level/queue_pos/start_time/end_time/status） | BuildingConstructedEvent / BuildingUpgradedEvent / BuildingUpgradeCancelledEvent |

## 六、结论与下一步

1. **现有 9 包可冻结为 v1**：查询面 + 运营管理面 + 事件 Schema 已自洽，冻结零风险；冻结规则见 4.1。
2. **六骨头契约缺口 = P3 新增项**：玩家档案/采集调度 ⚠️（数据面可复用，command/事件需新增）；建筑升级/背包道具/兵种训练/个人科技 ❌（需全新包）。**结论：全部走新增，不修改现有包**。
3. **新增契约遵循三原则**：独立命名空间 / command-事件-查询三面齐备 / 配置化优先（proto 只承载机制，数值留配置层）。
4. **下一步**：P3 立项时按 4.3 清单出 6 个完整 proto 文件与生成脚本；E16 题材扩展期补 C 类扩展点命名空间约定。
