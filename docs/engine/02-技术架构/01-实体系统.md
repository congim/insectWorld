# 技术架构 · 实体系统 

> 管理游戏中所有"东西"的生命周期和属性——是所有其他核心模块的根核心模块。

---

## 核心模块定义

**是什么**：管理游戏中所有"东西"的生命周期和属性——从一只蚂蚁到一座城池，都是实体。

**为什么是核心模块**：每个SLG都有实体。无论昆虫、三国还是星际，都需要创建/销毁/查询/修改"东西"。实体系统是所有其他核心模块的基础——地图上放的是实体，移动的是实体，战斗的是实体，生产资源的是实体。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| entity_types | 定义实体类型枚举 | 字符串数组，每个类型有唯一ID |
| entity_components | 定义实体可挂载的组件 | 组件ID→组件Schema映射 |
| entity_attributes | 定义实体的属性集 | 属性ID→{类型, 范围, 默认值}映射 |
| entity_tags | 定义实体的标签系统 | 标签字符串数组，用于查询过滤 |
| entity_creation_rules | 定义实体创建时的初始化规则 | 规则ID→{条件, 初始化动作}映射 |

## 框架默认行为

- 实体创建时自动分配唯一ID
- 实体销毁时自动触发 `entity.destroyed` 事件
- 实体属性变更时自动触发 `entity.attribute_changed` 事件
- 实体组件挂载/卸载时自动触发对应事件
- 默认支持实体池化，避免频繁创建/销毁的开销

## 约束

- 实体ID一旦分配不可变更
- 实体类型在创建后不可变更
- 组件的挂载/卸载必须在实体生命周期内完成
- 属性值必须符合属性定义的类型和范围约束

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_entities | 1,000,000 | 是 | 单服实体总数上限，超限拒绝创建 |
| max_components_per_entity | 32 | 是 | 单实体组件数上限，超限报错 |
| max_attributes_per_entity | 128 | 是 | 单实体属性数上限 |
| entity_id_strategy | snowflake | 是 | ID生成策略：snowflake/uuid/sequence |
| entity_pool_initial_size | 10,000 | 是 | 实体池初始大小（池化复用） |
| entity_pool_max_size | 100,000 | 是 | 实体池最大大小 |
| entity_query_timeout_ms | 50 | 是 | 实体查询超时阈值 |

## 与其他核心模块的关系

实体系统是**根核心模块**，所有其他核心模块都依赖它：

- **被地图系统依赖**：地图上放置的格子内容是实体
- **被移动系统依赖**：移动的主体是实体
- **被战斗系统依赖**：战斗的参与者是实体
- **被经济系统依赖**：资源的产出者/采集者/持有者是实体
- **被Buff系统依赖**：Buff的作用对象是实体，修改的是实体属性
- **被规则系统依赖**：规则的条件评估和动作执行针对实体
- **被联盟系统依赖**：联盟成员是实体（玩家实体）
- **被赛季系统依赖**：赛季排名和奖励的对象是实体
- **被网络同步依赖**：同步的核心数据是实体状态
- **被持久化依赖**：持久化的主要对象是实体
- **被配置加载框架依赖**：实体模板从配置加载

实体系统不依赖任何其他核心模块（除事件总线用于发出实体事件）。
