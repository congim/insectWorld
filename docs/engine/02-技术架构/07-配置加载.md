# 技术架构 · 配置加载框架 

> 配置文件的加载、校验、编译、热更机制——数据驱动框架的通用基础设施。

---

## 核心模块定义

**是什么**：配置文件的加载、校验、编译、热更机制。框架负责将JSON配置文件读取、校验、编译为内部数据结构、注册到对应扩展点，并在运行时支持配置热更。

**为什么是核心模块**：任何数据驱动的框架都需要配置管理。这是通用基础设施，不包含任何游戏特定逻辑。没有配置加载框架，扩展点契约无法落地——所有"内容配置"都以配置文件形式存在，需要统一的加载和校验机制。配置加载框架是"框架扩展接口"的物理实现层。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| config_file_definitions | 配置文件定义 | 文件名→{格式, 对应扩展点, 依赖文件}映射 |
| config_validation_schemas | 配置校验规则 | 文件名→JSON Schema映射，定义配置文件的合法结构 |
| config_dependencies | 配置依赖关系 | 文件名→依赖文件列表映射，决定加载顺序 |
| config_hotreload_policies | 配置热更策略 | 文件名→{可热更, 热更方式, 回滚策略}映射 |

### 扩展点详细说明

**扩展点1：配置文件定义**——框架定义配置文件格式（JSON），游戏填写配置内容

- 框架规定：配置文件必须是合法JSON，文件名符合 `^[a-z][a-z0-9_]*\.json$` 规范
- 框架规定：每个配置文件必须声明对应的扩展点（一个文件可对应多个扩展点）
- 游戏填写：具体的配置内容（如 `units.json` 中定义哪些兵种）

**扩展点2：配置校验规则**——框架提供校验器，游戏定义校验规则（JSON Schema）

- 框架提供：JSON Schema校验器、引用完整性校验器、自定义规则校验器、**配置包完整性校验器**、**配置包兼容性校验器**
- 游戏定义：每个配置文件的JSON Schema（约束字段类型、范围、必需性）
- 框架规定：校验失败的配置文件不会被加载，并抛出明确错误

**配置包完整性校验**（换皮/热更前置校验）：
- 校验18个配置文件是否齐全（对照配置包总清单）
- 校验必需文件不缺失（game/units/buildings/resources/terrains/formulas为必需，其余可选）
- 校验配置间依赖满足（如heroes.json引用的faction在factions.json中存在）
- 校验失败返回缺失文件清单+断链引用清单，拒绝加载

**配置包兼容性校验**（换皮/热更前置校验）：
- 校验新配置与存量数据Schema兼容（如新配置的resource_type是否覆盖存量玩家持有的资源类型）
- 校验新配置的terrain_id是否覆盖存量地图格子（避免存量格子引用不存在的地形）
- 校验新配置的unit_type是否覆盖存量玩家持有的兵种（避免存量兵种引用不存在的定义）
- 校验失败返回不兼容项清单，拒绝热更（避免新配置导致存量数据引用断裂）

**扩展点3：配置依赖关系**——框架按依赖顺序加载，游戏声明配置间引用

- 框架提供：拓扑排序加载器，自动计算加载顺序
- 游戏声明：配置文件间的依赖关系（如 `heroes.json` 依赖 `factions.json`）
- 框架规定：存在循环依赖时拒绝加载并报错

**扩展点4：配置热更策略**——框架支持热更，游戏定义哪些配置可热更

- 框架提供：文件监听器、原子替换机制、校验+回滚机制
- 游戏定义：哪些配置文件支持热更、热更方式（立即生效/下个tick生效/下个赛季生效）
- 框架规定：热更失败时自动回滚到上一个有效配置

## 框架默认行为

### 启动时加载流程

1. **全量加载**：按拓扑顺序读取所有配置文件
2. **校验**：对每个文件应用JSON Schema校验 + 自定义规则校验 + 引用完整性校验
3. **编译**：将JSON配置编译为内部数据结构（如将字符串ID解析为引用指针）
4. **注册**：将编译后的配置注册到对应扩展点
5. **错误处理**：任一必需配置文件校验失败，框架拒绝启动并报告错误

### 运行时热更流程

1. **文件监听**：监听启用了热更的配置文件变更
2. **校验**：对新配置执行完整校验
3. **原子替换**：校验通过后，原子替换内存中的配置数据
4. **回滚**：校验失败时回滚到上一个有效配置，发出 `config.reload_failed` 事件
5. **通知**：根据策略决定是否通知客户端

## 约束

- **配置文件必须可序列化**：所有配置必须是合法JSON，不支持二进制或代码
- **配置间引用必须无循环**：依赖关系必须是DAG（有向无环图），框架启动时检测
- **配置版本号必须递增**：每个配置文件必须包含 `version` 字段，热更时版本号必须递增
- **校验失败不降级**：校验失败的配置不会被部分加载，要么全部生效要么全部回滚
- **热更不破坏运行时状态**：热更只替换配置数据，不重置已运行的实体/战斗/赛季状态
- **必需配置不可缺失**：标记为 `required: true` 的配置文件缺失时框架拒绝启动

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_config_file_size_mb | 10 | 是 | 单配置文件大小上限 |
| max_total_config_size_mb | 100 | 是 | 所有配置文件总大小上限 |
| max_config_files | 50 | 是 | 配置文件数量上限 |
| config_load_timeout_seconds | 30 | 是 | 启动时配置加载总超时 |
| config_validation_timeout_seconds | 10 | 是 | 单文件校验超时 |
| hotreload_debounce_ms | 500 | 是 | 热更防抖间隔（避免频繁触发） |
| config_cache_strategy | lru | 是 | 配置缓存策略：lru/lfu/none |
| max_config_version_history | 10 | 是 | 保留的配置版本历史数（用于回滚） |

## 与其他核心模块的关系

配置加载框架**被所有核心模块依赖**（间接依赖，通过扩展点机制），但直接关系如下：

- **被实体系统依赖**：实体类型、组件、属性、标签、创建规则从配置加载（`units.json`、`buildings.json`、`heroes.json` 等）
- **被地图系统依赖**：地形、区域、通行性规则从配置加载（`map.json`）
- **被移动系统依赖**：移动类型、消耗表、编队规则从配置加载（`movement.json`）
- **被战斗系统依赖**：战斗类型、伤害公式、克制矩阵、技能从配置加载（`combat.json`）
- **被经济系统依赖**：资源类型、生产/采集/交易规则从配置加载（`resources.json`、`economy.json`）
- **被Buff系统依赖**：Buff类型、效果、叠加/触发/光环/驱散规则从配置加载（`buffs.json`）
- **被规则系统依赖**：规则定义、规则组、条件库、动作库从配置加载（`rules.json`）
- **被联盟系统依赖**：联盟等级、权限、外交状态从配置加载（`alliance.json`）
- **被赛季系统依赖**：赛季阶段、事件、奖励、重置规则从配置加载（`season.json`）
- **被网络同步依赖**：同步范围、优先级、重连规则从配置加载（`sync.json`）
- **被持久化依赖**：持久化实体、触发器、迁移脚本从配置加载（`persistence.json`）
- **依赖事件总线**：热更成功/失败发出事件（`config.reloaded`、`config.reload_failed`）

配置加载框架是"框架扩展接口"的物理实现层——第三章定义的所有扩展点契约，都通过配置加载框架落地。没有配置加载框架，扩展点契约只是纸面约定；有了它，契约变为可执行的校验逻辑。
