# 技术架构 · 事件总线 

> 核心模块间通信的核心机制——所有核心模块之间的通信通过事件完成，核心模块之间不直接调用。

---

## 核心模块定义

**是什么**：事件总线是核心模块间通信的核心机制，提供事件的发布/订阅/派发能力。所有核心模块之间的通信必须通过事件总线完成，核心模块之间禁止直接调用。

**为什么是核心模块**：任何多模块系统都需要解耦通信。事件总线是通用基础设施，不包含任何游戏特定逻辑。没有事件总线，核心模块之间将形成紧耦合的网状依赖，无法独立演进和替换。事件总线将网状依赖降为星型依赖（所有核心模块只依赖事件总线），是框架可维护性的根基。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| event_types | 事件类型定义 | 事件类型字符串，命名空间格式 `module.event_name` |
| event_handlers | 事件处理器注册 | 事件类型→{处理器ID, 优先级, 条件}映射 |
| event_priorities | 事件优先级 | 事件类型→优先级策略映射，决定同事件多处理器执行顺序 |
| event_filters | 事件过滤规则 | 规则ID→{事件类型, 过滤条件}映射，减少不必要的派发 |

游戏可以定义新的事件类型（通过配置注册），但不能修改事件总线的派发机制。

## 扩展点契约

事件总线不通过传统的扩展点契约注册，而是通过**事件类型约定**和**处理器注册**实现扩展。以下是框架定义的完整事件类型表，每个事件类型即是一个隐式扩展点。

## 框架默认行为

- **同步派发**：同一tick内按注册顺序执行所有处理器
- **事件不可变**：事件数据在发布后不可修改，保证多处理器看到一致的数据
- **支持优先级**：同一事件的多个处理器按优先级顺序执行
- **失败隔离**：单个处理器执行失败不影响后续处理器
- **超时保护**：事件分发有超时保护，防止单个处理器阻塞整个总线
- **递归保护**：事件处理器内不可同步发布同类事件，防止递归风暴

## 约束

- **核心模块间禁止直接调用**：所有核心模块间通信必须通过事件总线
- **事件数据不可修改**：事件发布后，任何处理器不可修改事件携带的数据
- **事件处理不能阻塞**：处理器必须快速返回，耗时操作应异步化
- **事件类型命名规范**：必须使用 `module.event_name` 格式（如 `entity.created`、`combat.ended`）
- **事件类型不可动态修改**：框架启动后不可删除已有事件类型，只可新增

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_handlers_per_event | 50 | 是 | 单事件最大处理器数，超限拒绝注册 |
| event_queue_size | 10,000 | 是 | 事件队列容量，满则按策略丢弃/阻塞 |
| event_dispatch_timeout_ms | 20 | 是 | 单处理器派发超时，超时跳过该处理器 |
| max_event_data_size_kb | 64 | 是 | 单事件携带数据大小上限 |
| event_recursion_limit | 2 | 是 | 同事件递归派发最大深度 |
| async_event_worker_count | 4 | 是 | 异步事件处理worker数 |
| event_batch_size | 100 | 是 | 每tick批量派发事件数上限 |

## 与其他核心模块的关系

事件总线是**根核心模块**，所有核心模块都依赖它：

- **被实体系统依赖**：实体创建/销毁/属性变更等发出事件
- **被移动系统依赖**：移动开始/到达/阻挡等发出事件
- **被战斗系统依赖**：战斗开始/结束/伤害等发出事件
- **被经济系统依赖**：资源生产/变更/不足等发出事件
- **被地图系统依赖**：地形变更/区域变更等发出事件
- **被Buff系统依赖**：Buff挂载/移除/触发等发出事件，同时监听触发式Buff的事件
- **被规则系统依赖**：规则的触发依赖于事件（`trigger_event`），规则执行发出 `rule.executed` 事件
- **被联盟系统依赖**：联盟创建/解散/外交变更等发出事件
- **被赛季系统依赖**：赛季开始/阶段切换/结束等发出事件
- **被网络同步依赖**：关键事件即时同步到客户端
- **被持久化依赖**：关键事件触发存档，元事件用于错误记录

事件总线不依赖任何其他核心模块（它是通信基础设施，自身不包含游戏逻辑）。

事件总线与实体系统同为框架的两个根核心模块：实体系统是"数据根"（所有数据的载体），事件总线是"通信根"（所有交互的通道）。
