# 技术架构 · 网络同步 

> 为多人在线SLG提供状态同步的框架级支持——增量同步、断线重连、房间管理。

---

## 核心模块定义

**是什么**：为多人在线SLG提供状态同步的框架级支持——增量同步、断线重连、房间管理。

**为什么是核心模块**：SLG天然是多人游戏。网络同步是技术基础设施，与游戏内容无关。框架提供同步机制，具体同步频率和策略由内容配置。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| sync_scope_rules | 同步范围规则 | 规则ID→{实体类型, 同步范围, 同步频率}映射 |
| sync_priority_rules | 同步优先级 | 规则ID→{数据类型, 优先级, 压缩策略}映射 |
| sync_state_definitions | 同步状态定义 | 状态ID→{字段列表, 增量策略}映射 |
| room_rules | 房间规则 | 规则ID→{房间类型, 容量, 匹配条件}映射 |
| reconnection_rules | 重连规则 | 规则ID→{超时时间, 状态恢复策略}映射 |
| sync_validation_rules | 同步校验 | 规则ID→{校验字段, 校验方式, 作弊处理}映射 |

## 框架默认行为

- 默认同步范围：玩家视野内
- 默认同步频率：关键事件即时同步，属性变更每秒同步
- 默认增量同步：只同步变化的字段
- 默认断线重连超时：5分钟
- 默认重连策略：全量状态快照 + 增量补丁
- 默认无房间匹配

## 约束

- 同步数据必须可序列化
- 客户端不可信任（服务端校验）
- 断线期间的状态变更在重连后补发
- 同步失败触发 `sync.error` 事件

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_messages_per_tick | 1,000 | 是 | 每tick最大发送消息数，超限排队下tick |
| max_message_size_kb | 256 | 是 | 单消息大小上限 |
| sync_bandwidth_limit_kbps | 0（不限） | 是 | 每客户端带宽限制 |
| max_concurrent_connections | 10,000 | 是 | 最大并发连接数 |
| heartbeat_interval_seconds | 15 | 是 | 心跳间隔 |
| connection_timeout_seconds | 60 | 是 | 连接超时（无心跳判定离线） |
| reconnection_grace_seconds | 300 | 是 | 断线重连宽限期 |
| max_snapshot_size_mb | 10 | 是 | 全量快照大小上限（重连时发送） |

## 与其他核心模块的关系

网络同步是**横切关注点**，依赖所有核心模块（需要同步所有核心模块的状态）：

- **依赖实体系统**：同步实体状态（位置、属性、组件）
- **依赖移动系统**：同步移动状态（路径、位置）
- **依赖战斗系统**：同步战斗状态（参战方、战报）
- **依赖经济系统**：同步资源状态（持有量、变更）
- **依赖地图系统**：同步视野状态（可见格子）
- **依赖Buff系统**：同步Buff状态（挂载、移除、层数）
- **依赖联盟系统**：同步联盟状态（成员、外交）
- **依赖赛季系统**：同步赛季状态（阶段、排名）
- **依赖规则系统**：同步规则执行结果
- **依赖事件总线**：监听关键事件触发即时同步
- **依赖持久化**：重连时从持久化恢复状态

网络同步不提供任何游戏逻辑，只负责将其他核心模块的状态在服务端和客户端之间传输。
