# 技术架构

> 与游戏类型无关的基础设施。换成RPG/MOBA/RTS同样需要这些机制。

## 包含的核心模块

| # | 核心模块 | 职责 | 依赖 |
|---|------|------|------|
| 1 | [实体系统](01-实体系统.md) | 游戏中所有"东西"的生命周期和属性管理 | 无（根核心模块） |
| 2 | [Buff系统](02-Buff系统.md) | 属性的临时/永久修改机制 | 实体 |
| 3 | [规则系统](03-规则系统.md) | "当X发生时，做Y"的触发-动作引擎 | 事件总线、实体、Buff |
| 4 | [事件总线](04-事件总线.md) | 核心模块间通信的核心机制 | 无（根核心模块） |
| 5 | [网络同步](05-网络同步.md) | 服务端-客户端数据同步机制 | 所有核心模块 |
| 6 | [持久化](06-持久化.md) | 数据存储和恢复 | 所有核心模块 |
| 7 | [配置加载](07-配置加载.md) | 配置文件的加载、校验、热更 | 实体 |

## 设计原则

- 技术架构核心模块不包含任何SLG特有概念（不出现"军队""城池""赛季"等词）
- 技术架构核心模块可以被其他游戏类型复用
- 技术架构核心模块之间通过事件总线通信，不直接调用
