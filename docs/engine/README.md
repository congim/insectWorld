# 通用SLG框架设计书

> 版本：v3.3 | 最后更新：2026-08-06
> 核心理念：引擎-配置分离。核心模块是框架提供的通用机制，内容配置是游戏配置挂载的具体内容。换皮=换配置，引擎核心不改。
> 架构模型：服务端权威。服务端是唯一真相源，客户端负责渲染、输入转发和体验优化预测。

## 14根核心模块总览

### 技术架构（7根）——与游戏类型无关
| # | 核心模块 | 职责 |
|---|------|------|
| T1 | 实体系统 | 游戏对象的通用生命周期管理 |
| T2 | Buff系统 | 属性的临时/永久修改机制 |
| T3 | 规则系统 | "当X发生时，做Y"的触发-动作引擎 |
| T4 | 事件总线 | 核心模块间通信的核心机制 |
| T5 | 网络同步 | 服务端-客户端数据同步机制 |
| T6 | 持久化 | 数据存储和恢复 |
| T7 | 配置加载 | 配置文件的加载、校验、热更 |

### 业务架构（7根）——SLG特有
| # | 核心模块 | 职责 |
|---|------|------|
| B1 | 地图系统 | SLG空间模型：网格、地形、领土 |
| B2 | 移动系统 | 军队行军、路径规划、拦截 |
| B3 | 战斗系统 | 冲突解决：伤害、流程、战报 |
| B4 | 经济系统 | 资源流转：产出、采集、贸易 |
| B5 | 联盟系统 | 玩家组织：外交、战争、科技 |
| B6 | 赛季系统 | 周期运营：阶段、重置、遗产 |
| B7 | 事件系统 | 游戏事件：天气、天灾、随机 |

## 约定

- 核心模块：框架内置的通用机制
- 内容配置：游戏配置的具体内容
- 扩展点：核心模块暴露给内容配置的接口
- 接口契约：扩展点的输入输出约束
- 约束：框架层面的硬性限制
