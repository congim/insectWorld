# 通用性验证

> 状态：历史验证入口。早期材料以“玩法能映射到某个模块或扩展点”作为覆盖，不能证明契约具备完整表达力。现行标准见[产品与平台边界](../../product/产品与平台边界.md)。

## 保留目的

昆虫、三国和星际三个题材具有明显差异，适合用于发现隐含的题材耦合。它们现在承担三种作用：

1. 作为领域建模的反例库；
2. 为扩展接口提供第二用例；
3. 检查通用内核是否泄漏具体题材词汇和数值。

三国和星际不是并行开发的产品，也不要求建立完整配置包。

## 现行验证方法

每个候选通用能力按以下步骤验证：

1. 从昆虫世界垂直切片提取真实需求；
2. 写出输入、输出、失败语义、版本和性能约束；
3. 用第二个不同用例实现同一契约；
4. 运行两个用例的契约测试；
5. 确认第二用例没有修改通用内核；
6. 无法共用时，将差异留在游戏扩展，不继续扩大配置语言。

不再计算“通用性百分比”。单纯增加扩展点数量会提高旧评分，却可能降低可维护性。

## 下一次验证的最小范围

首个真实验证只选择三项高风险能力：

- 战斗公式：昆虫战斗与一个最小传统战斗用同一求值契约；
- 移动成本：昆虫地形与一个最小星际航路用同一接口或明确分流为扩展；
- 配置版本：两个游戏包都能校验引用、绑定运行实例并安全升级。

只有测试通过的部分才写入通用能力清单。
