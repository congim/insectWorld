# 通用性验证

> 用三个差异极大的SLG题材验证框架的通用性。验证方法：每个题材列出核心玩法特征，映射到框架核心模块和内容配置，检查是否有玩法特征无法被框架覆盖。

---

## 4.1 验证方法

**四步验证法**：

1. **列出题材的核心玩法特征**：每个题材列出5-10个最核心的玩法特征
2. **映射到框架核心模块**：每个玩法特征映射到哪根（或哪几根）核心模块提供机制支撑
3. **映射到框架内容配置**：每个玩法特征需要配置哪些内容配置（扩展点）来实现
4. **检查覆盖度**：统计14根核心模块的使用情况和扩展点覆盖情况，找出框架无法覆盖的玩法特征

**通用性评分标准**：

| 评分 | 标准 |
|------|------|
| 100% | 所有玩法特征均可通过核心模块+内容配置实现，无需修改框架 |
| 90%+ | 少数玩法特征需要新增扩展点，但不需要新增核心模块 |
| 80%+ | 部分玩法特征需要新增核心模块 |
| <80% | 框架通用性不足，需要重大修改 |

### 框架缺陷检查

| 检查项 | 结果 | 说明 |
|--------|------|------|
| 是否有玩法特征无法被任何核心模块覆盖？ | ❌ 无 | 所有玩法特征均可映射到核心模块 |
| 是否有玩法特征需要新增核心模块？ | ❌ 无 | 无需新增核心模块 |
| 是否有玩法特征需要新增扩展点？ |  可能 | 信息素路径的"路径标记"机制可能需要movement系统新增一个扩展点（movement_path_markers），但也可以通过规则系统+事件系统组合实现 |
| 三层战斗是否需要特殊支持？ | ❌ 否 | 通过三种combat_types + 规则系统层间流转实现 |
| 三维地图是否需要特殊支持？ |  可能 | free格子类型+自由坐标可以覆盖，但三维空间的距离计算可能需要在map系统新增一个扩展点（map_distance_formula） |

### 验证结论

| 指标 | 结果 |
|------|------|
| 核心模块覆盖率 | 14/14 = 100% |
| 玩法特征覆盖率 | 24/24 = 100%（所有特征均可通过核心模块+内容配置实现） |
| 需要新增扩展点 | 2个可能（movement_path_markers, map_distance_formula），但均可通过现有机制组合替代 |
| 需要新增核心模块 | 0 |
| **通用性评分** | **100%** |

### 口径修订说明（2026-08-11，契约表达力级核查后）

> ⚠️ **本文档的 "24/24 = 100%" 为文档映射级结论**。经 `docs/engine/06-扩展指南/契约表达力缺口对照表.md`（契约表达力级核查）量化校正后，**配置化承诺的真实覆盖率约为 71%（严格口径）/ 83%（宽松口径）**。

| 口径 | 覆盖率 | 含义 |
|------|--------|------|
| 文档映射级（本 README 原结论） | 24/24 = 100% | 每个玩法特征均映射到核心模块/扩展点名，"扩展点存在"即计覆盖 |
| 契约表达力级（对照表修正） | 17/24 ≈ 71%（严格）/ 20/24 ≈ 83%（宽松） | 逐特征核查"扩展点字段/语义、内置 7 动作、公式引擎 12 能力、机制骨头"是否真实承载，存在缺口即降档 |

**差异原因**：映射级核查验证的是"模块/扩展点覆盖"——凡特征能映射到扩展点名即计 100%；表达力级核查进一步追问"扩展点契约的字段与语义能否承载该特征所需的全部能力"，对 24 个特征逐项核对了 07 配置包总清单 Schema、ADR-003 内置 7 动作、ADR-001 公式函数库与 P3 新骨头建设状态。差额 7 个特征（29.2%）对应三类缺口：扩展点字段缺口（信息素场/随机目的地）、动作缺口（change_owner/题材层战斗阶段动作）、机制骨头缺口（建筑升级/个人科技，属 P3 计划内）。

**修正不推翻验证方法**：四步验证法成立，14 根核心模块全题材覆盖、框架零 diff 扩展机制均有效；修正的是"覆盖率表述"——从"扩展点存在"的乐观估计，校准到"契约能力真实承载"的保守口径。契约冻结层面的落点见 [契约冻结草案](../08-客户端契约/契约冻结草案_2026-08-11.md)。

框架的引擎-配置分离设计成功通过了三个差异极大的SLG题材验证。所有玩法特征均可通过14根核心模块+内容配置实现，无需修改框架代码。
