# 安全设计

> 服务端权威架构下，安全是硬性约束。鉴权、传输加密、防作弊、DDoS防护四条线缺一不可。

---

## 安全分层

```
客户端
  │
  ├─ 1.传输层：WSS（WebSocket over TLS）
  │
  ├─ 2.接入层：Gateway鉴权（JWT校验+签名校验）
  │
  ├─ 3.服务间：mTLS双向认证 + gRPC鉴权
  │
  ├─ 4.业务层：服务端权威校验（防作弊）
  │
  └─ 5.数据层：存储加密 + 审计日志
```

---

## 鉴权设计

### 客户端鉴权（Gateway层）

| 阶段 | 机制 | 说明 |
|------|------|------|
| 登录 | 账号密码/三方OAuth | 登录服务校验，签发JWT（含玩家ID+权限+过期时间） |
| 连接 | WSS握手携带JWT | Gateway校验JWT签名+过期，拒绝非法连接 |
| 请求 | 每请求携带JWT或session_id | Gateway校验session有效性，限流防刷 |
| 续期 | JWT临近过期自动续期 | 客户端在过期前刷新token，无感续期 |

**JWT设计**：
- 算法：EdDSA（Ed25519），不用HS256（对称密钥泄露风险）。
- Payload：`{player_id, alliance_id, role, exp, iat, jti}`，jti为token唯一ID用于吊销。
- 签发方：登录服务（独立于Gateway，持有私钥）。
- 校验方：Gateway持有公钥验签，不存session（无状态）。
- 吊销：jti黑名单存Redis（TTL=token剩余有效期），登出/封号时写入。

### 服务间鉴权（mTLS）

| 项 | 配置 |
|----|------|
| CA | 内部CA（自签根证书），服务实例证书由CA签发 |
| 证书签发 | 短期证书（mTLS SPIFFE，证书有效期<24h），自动轮换 |
| 双向认证 | gRPC双方互验证书，拒绝无证书或非本CA签发的连接 |
| 服务身份 | 证书SAN含服务名（如 `spiffe://insectworld/combat`），用于授权 |
| 授权 | 基于服务身份的ACL：Combat可调Social.GetPlayerAttributes，不可调Economy.Transfer |

**为什么mTLS而非Token**：服务间调用频繁，每次签发/校验Token开销大；mTLS在连接建立时一次认证，后续复用连接；短期证书自动轮换比Token吊销更轻量。

### 运营管理鉴权（AdminService）

运营管理操作（配置热更、赛季管理、玩家封禁等）通过独立的AdminService gRPC接口提供，鉴权要求高于玩家操作：

| 项 | 要求 |
|----|------|
| 鉴权 | 运营管理员Token（独立于玩家JWT，由内部OA系统签发），AdminService校验Token有效性+管理员身份 |
| 权限分级 | 不同管理员有不同操作权限（如配置管理员只能ReloadConfig，赛季管理员只能ForceTransitionPhase），基于RBAC |
| 二次确认 | 危险操作（ForceResetSeason/RollbackConfig/BanPlayer永久封禁）需要 confirm=true 参数，防止误操作 |
| 频率限制 | 管理操作频率限制（避免误操作批量触发）：ForceResetSeason 1次/分钟、BanPlayer 10次/分钟、ReloadConfig 1次/分钟 |
| 来源限制 | 管理操作仅接受来自内网管理后台的请求（IP白名单），拒绝外网直接调用 |

### 审计日志

所有运营管理操作必须记录审计日志，append-only不可篡改：

| 字段 | 说明 |
|------|------|
| admin_id | 操作人ID |
| timestamp | 操作时间 |
| operation | 操作类型（ReloadConfig/BanPlayer等） |
| target | 操作目标（config_version/player_id/season_id等） |
| params | 操作参数 |
| result | 操作结果（成功/失败+错误码） |
| source_ip | 来源IP |

审计日志写入独立的审计存储（append-only，禁止update/delete），保留期≥180天，支持按操作人/时间/操作类型查询。审计日志本身也是安全审计对象（记录"谁查了审计日志"）。

## 传输加密

| 链路 | 加密 | 说明 |
|------|------|------|
| 客户端↔Gateway | WSS（TLS 1.3） | 拒绝降级，仅允许TLS1.3 |
| 服务间 | mTLS（TLS 1.3） | gRPC over mTLS |
| 服务↔存储 | TLS | Redis 6+ TLS、MySQL TLS连接、MongoDB TLS |
| 内部网络 | VPC隔离 + mTLS | 双重防护，即使内网被突破也有mTLS |

## 防作弊设计

**核心理念**：服务端权威，客户端输入只作为"意图声明"，所有业务校验和结算在服务端完成。客户端预测仅为体验优化，不作为真相。

### 客户端输入校验清单

| 输入类型 | 校验内容 | 反作弊措施 |
|---------|---------|-----------|
| 移动请求 | 目标坐标是否可达、移动CD、行军令是否合法 | 服务端独立做寻路校验，拒绝客户端给的路径 |
| 战斗请求 | 参战方是否在场、是否可攻击、兵力是否一致 | 服务端校验参战方状态，兵力以服务端为准 |
| 资源操作 | 余额是否足够、操作频率、数量上下限 | 服务端校验余额，限流防刷 |
| 联盟操作 | 权限校验、成员上限、操作频率 | 服务端校验玩家在联盟中的权限 |
| 配置/赛季 | 客户端不可操作 | 配置/赛季操作仅限运营后台（独立鉴权） |

### 速率与行为异常检测

| 异常 | 检测 | 处置 |
|------|------|------|
| 高频请求（刷接口） | 单玩家QPS>阈值 | 限流降级，超限告警 |
| 跨区域瞬移 | 客户端位置突变（>合理速度） | 服务端按服务端位置为准，拒绝非法位置 |
| 战斗属性异常 | 客户端上报属性与服务端快照不符 | 以服务端快照为准，记录疑似作弊日志 |
| 多开/脚本 | 同IP多账号+行为模式机械 | 风控系统识别，限制或封号 |

### 客户端预测的边界

客户端可做预测渲染（如移动预览、战斗动画），但**所有最终结果以服务端推送为准**。客户端预测与服务端结果冲突时，客户端硬同步服务端结果（"回滚校正"）。这保证即使客户端被篡改也不影响服务端真相。

## DDoS防护

| 层 | 防护 | 说明 |
|----|------|------|
| 边缘 | CDN/高防IP清洗 | 大流量DDoS在边缘清洗，不进机房 |
| Gateway | 连接限速+IP限速+玩家限速 | 单IP连接数限制、单IP新建连接速率限制、单玩家QPS限制 |
| Gateway | WebSocket握手校验 | 非法握手（无JWT/签名错）快速拒绝，不消耗业务资源 |
| 服务间 | gRPC限流+熔断 | 防止级联雪崩 |
| 存储 | 连接池上限 | 防止连接耗尽 |

**慢速攻击防护**：WebSocket长连接可能被用于慢速攻击（建连后不发数据占连接）。Gateway对空闲连接设心跳超时（30秒无心跳断开），限制单IP长连接数。

## 数据安全

| 数据 | 保护 | 说明 |
|------|------|------|
| 玩家敏感信息（账号/手机） | 加密存储 + 脱敏展示 | 手机号脱敏显示，数据库字段级加密 |
| 密码 | bcrypt/argon2 哈希 | 不存明文，不存可逆加密 |
| 战报/聊天 | 内容审计 | 违规内容检测，敏感词过滤 |
| 配置/赛季数据 | 完整性校验 | 配置文件签名校验，防篡改 |
| 审计日志 | 不可篡改 | 关键操作（封号/发奖/配置改）写审计日志，append-only |

## 密钥与证书管理

| 密钥 | 存储 | 轮换 |
|------|------|------|
| JWT签名私钥 | KMS（云密钥管理）/ Vault | 定期轮换（90天），旧公钥保留验证期内token |
| mTLS CA私钥 | 离线保管 | 根CA长期，中间CA短期 |
| 服务mTLS证书 | SPIFFE自动签发 | <24h自动轮换 |
| 存储密码 | KMS/Vault | 不入仓，运行时注入 |
| 三方API密钥 | KMS/Vault | 不入仓 |

**禁止项**：密钥不入代码仓、不进镜像、不打日志、不在错误信息中返回。
