# 可观测性

> 三个支柱：指标（Metrics）、日志（Logs）、链路追踪（Traces）。统一用OpenTelemetry采集，Prometheus+Loki+Tempo存储，Grafana可视化。

---

## 指标体系

采用 RED 原则（Rate、Errors、Duration）+ 业务指标。

### 通用技术指标（每服务必采）

| 指标 | 类型 | 说明 |
|------|------|------|
| `http_requests_total` | Counter | 请求总数（按method/path/status） |
| `http_request_duration_seconds` | Histogram | 请求延迟分布（P50/P95/P99） |
| `grpc_requests_total` | Counter | gRPC调用总数（按service/method/status） |
| `grpc_request_duration_seconds` | Histogram | gRPC延迟分布 |
| `nats_published_total` | Counter | 事件发布数（按event_type） |
| `nats_consumed_total` | Counter | 事件消费数（按event_type） |
| `nats_lag` | Gauge | 事件积压数（Outbox未投递/消费者滞后） |
| `outbox_pending` | Gauge | Outbox表待投递事件数 |
| `outbox_oldest_age_seconds` | Gauge | Outbox最老未投递事件年龄（积压时长） |
| `repository_operation_duration_seconds` | Histogram | 仓储操作延迟（按repo/op） |
| `cache_hit_ratio` | Gauge | 缓存命中率（按cache_name） |
| `goroutines_count` | Gauge | goroutine数（防泄漏） |
| `memory_heap_bytes` | Gauge | 堆内存（防泄漏） |
| `config_reload_pending_count` | Gauge | 未确认最新配置热更的服务数量（跨服务配置一致性） |
| `config_reload_duration_seconds` | Histogram | 各服务配置热更reload耗时 |
| `config_reload_success_total` | Counter | 配置热更成功次数（按service） |
| `config_reload_failure_total` | Counter | 配置热更失败次数（按service+error_code） |
| `config_validation_duration_seconds` | Histogram | 配置校验耗时（完整性+兼容性+业务规则） |
| `config_version` | Gauge | 当前生效配置版本号（按service） |

### 业务指标（按服务）

| 服务 | 指标 | 类型 | 说明 |
|------|------|------|------|
| World | `movement_active_count` | Gauge | 进行中移动数 |
| World | `movement_cross_region_total` | Counter | 跨区域移动数 |
| World | `rebalance_in_progress` | Gauge | rebalance进行中标记 |

| Combat | `combat_migration_total` | Counter | 战斗迁移次数（故障恢复） |
| Combat | `combat_settle_draw_total` | Counter | 平局兜底结算次数（应趋近0） |
| Economy | `resource_operation_total` | Counter | 资源操作数（按op_type） |
| Economy | `saga_compensation_total` | Counter | Saga补偿次数（按result） |

## 日志规范

### 结构化日志格式

统一用 zap 结构化日志，JSON输出，字段规范：

```json
{
  "ts": "2026-08-06T15:30:00.123Z",
  "level": "info",
  "service": "combat",
  "trace_id": "abc123",
  "span_id": "def456",
  "player_id": "p_001",
  "combat_id": "c_999",
  "msg": "combat_round_completed",
  "round": 3,
  "damage": 1200,
  "duration_ms": 45
}
```

### 日志级别约定

| 级别 | 使用场景 |
|------|---------|
| ERROR | 影响业务的错误（写库失败、事件投递失败、聚合根不变量违反） |
| WARN | 可降级的异常（重试成功、熔断触发、缓存降级、快照过期校正） |
| INFO | 关键业务节点（战斗开始/结束、赛季切换、配置热更、玩家上线） |
| DEBUG | 调试细节（聚合根状态变更、规则条件评估），生产默认关 |

### 日志禁忌

- 不打敏感数据（密码/token/手机号明文）。
- 不打大对象全量（如完整战报，只打ID+摘要）。
- ERROR必须有人处理（告警联动），不产生无人看的ERROR。

## 链路追踪

### 采样策略

| 场景 | 采样率 | 说明 |
|------|--------|------|
| 正常请求 | 1% | 降低开销，够看分布 |
| ERROR请求 | 100% | 错误必追全链路 |
| 慢请求（>P99） | 100% | 慢必追根因 |
| 战斗全流程 | 100% | 战斗是高价值场景，全追 |
| 跨服务事件链 | 100% | 事件驱动链路难调，全追 |

### 关键链路埋点

| 链路 | 埋点span |
|------|---------|
| 客户端→Gateway→业务服务 | Gateway span + 业务服务 span |
| 服务间gRPC | client span + server span |
| 事件发布→消费 | publish span（Outbox写入）+ deliver span（relay投递）+ consume span |
| 聚合根操作 | application span + domain span（聚合根方法）+ repo span |
| 跨区域移动 | 源分片 span + 迁移 span + 目标分片 span |

### 事件链路追踪

事件驱动链路通过 `trace_id` 传递：发布事件时将当前 `trace_id` 写入事件头，消费者处理事件时继承该 `trace_id`，形成跨服务的事件链路。Outbox投递的relay也继承 `trace_id`，保证"写聚合根→投递事件→消费处理"全链路可追。

## 告警规则

### 告警分级

| 级别 | 响应 | 通知方式 |
|------|------|---------|
| P0（紧急） | 立即响应（<5分钟） | 电话+短信+IM |
| P1（严重） | 快速响应（<30分钟） | 短信+IM |
| P2（一般） | 工作时间内响应 | IM |
| P3（提示） | 关注即可 | 仪表盘 |

### 核心告警规则

| 告警 | 条件 | 级别 | 处置 |
|------|------|------|------|
| 服务不可用 | 健康检查失败持续>30秒 | P0 | 自动故障转移+人工确认 |
| 错误率飙升 | 错误率>1% 持续1分钟 | P1 | 查日志定位+自动扩容 |
| 延迟飙升 | P99>500ms 持续2分钟 | P1 | 查链路追踪+扩容 |
| Outbox积压 | `outbox_oldest_age_seconds`>60 | P1 | 查NATS连通性+relay状态 |
| 配置热更未一致 | `config_reload_pending_count`>0 持续>30秒 | P1 | 查未确认服务的watcher状态+etcd连通性 |
| 配置热更失败 | `config_reload_failure_total`增量>0 | P1 | 查校验失败原因（完整性/兼容性/业务规则） |
| 配置校验耗时高 | `config_validation_duration_seconds`P99>5秒 | P2 | 查配置包大小+校验规则复杂度 |
| 事件消费滞后 | `nats_lag`>10000 持续5分钟 | P1 | 查消费者健康+扩消费者 |
| 战斗平局兜底 | `combat_settle_draw_total`增量>0 | P1 | 战斗迁移失败，查Redis状态 |
| Saga卡住 | `saga_stuck_count`>0 | P2 | 人工介入处理补偿 |
| 缓存命中率低 | `cache_hit_ratio`<70% 持续10分钟 | P2 | 查缓存容量+预热 |
| goroutine泄漏 | `goroutines_count`持续增长 | P2 | 查pprof |
| 磁盘将满 | 磁盘使用>85% | P2 | 扩容/清理 |
| 证书将过期 | mTLS证书剩余<7天 | P3 | 确认自动轮换 |

### 告警去噪

- 同一告警5分钟内只发一次（防风暴）。
- 关联告警合并（如某服务挂了，其下游错误告警合并为一条）。
- 维护期告警静默（发布/维护窗口预设静默）。
