# 业务架构 · 地图系统 

> 管理游戏世界的空间结构——格子、地形、区域、视野，是移动、战斗、资源产出的空间基础。

---

## 核心模块定义

**是什么**：管理游戏世界的空间结构——格子、地形、区域、视野。

**为什么是核心模块**：每个SLG都有地图。无论六角格、四角格还是自由坐标，都需要空间管理。地图系统决定了实体"在哪里"，是移动、战斗、资源产出的空间基础。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| map_grid_type | 地图格子类型 | 枚举：hex / quad / free |
| map_dimensions | 地图尺寸 | {width, height} 或 {radius} |
| terrains | 地形定义 | 地形ID→{通行性修正, 视野修正, 效果列表}映射 |
| map_regions | 区域定义 | 区域ID→{格子集合, 区域属性}映射 |
| map_passability_rules | 通行性规则 | 规则列表，决定哪些实体能进入哪些地形 |
| map_vision_rules | 视野规则 | 规则列表，决定视野计算方式 |

| 字段 | 值 |
|------|---|
| extension_point_id | map.map_grid_type |

| input_contract | `{ "type": "string", "schema": { "enum": ["hex", "quad", "free"] }, "required": true }` |

## 框架默认行为

- 默认六角格地图（SLG最常见）
- 默认地形全部可通行
- 默认视野为周围1圈
- 默认无区域划分
- 地图边界不可越界

## 约束

- 地图尺寸一旦创建不可变更
- 格子坐标由框架管理，内容配置不可直接修改
- 地形变更触发 `map.terrain_changed` 事件
- 区域可以动态创建/销毁

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_map_width | 1,000 | 是 | 地图最大宽度（格子数） |
| max_map_height | 1,000 | 是 | 地图最大高度（格子数） |
| max_regions | 500 | 是 | 区域总数上限 |
| max_region_hierarchy_depth | 5 | 是 | 区域层级最大深度（父区域嵌套） |
| vision_calc_interval_ticks | 10 | 是 | 视野计算间隔（tick数），避免每tick全量重算 |
| max_terrain_types | 50 | 是 | 地形类型数量上限 |
| map_cell_data_size_bytes | 16 | 是 | 单格子数据大小（坐标+地形ID+区域ID） |

## 与其他核心模块的关系

- **依赖**：实体系统（L0层）——地图上的所有内容物都是实体，地图提供空间坐标，实体占据格子。
- **被依赖**：
  - 移动系统（L1层）——移动需要地图的格子、地形、通行性规则来计算路径。
  - 战斗系统（L2层）——战斗需要地图的地形效果、区域判定（如攻城战在城池区域）。
  - 经济系统（L1层）——资源产出依赖地图区域（如州郡肥沃度影响粮食产出）。
- **层级定位**：L0层基础核心模块，是空间类业务的根依赖。
