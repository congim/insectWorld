# 业务架构 · 移动系统 

> 计算和管理实体在地图上的移动——路径搜索、移动力消耗、编队移动、传送，连接地图与实体的桥梁。

---

## 核心模块定义

**是什么**：计算和管理实体在地图上的移动——路径搜索、移动力消耗、编队移动、传送。

**为什么是核心模块**：每个SLG都有移动。无论行军、飞行还是跃迁，都需要从A到B的移动计算。移动系统连接地图（空间）和实体（移动者），是战斗和探索的前置条件。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| movement_types | 移动类型定义 | 类型ID→{移动力公式, 地形修正表}映射 |
| movement_costs | 移动力消耗表 | {地形, 移动类型}→消耗值映射 |
| movement_formation_rules | 编队规则 | 编队类型→{队形, 速度修正}映射 |
| movement_teleport_rules | 传送规则 | 传送类型→{条件, 冷却, 目标约束}映射 |
| movement_blocking_rules | 阻挡规则 | 规则列表，决定哪些实体阻挡哪些移动 |
| movement_path_modifiers | 路径修正器 | 修正器ID→{条件, 路径偏好/惩罚}映射 |

## 框架默认行为

- 默认A*路径搜索
- 默认移动力=实体speed属性
- 默认地形消耗=1
- 默认无编队（单实体移动）
- 默认无传送
- 默认敌对实体阻挡通行

## 约束

- 移动请求必须指定目标位置（格子坐标或实体ID）
- 移动过程中实体状态锁定为"移动中"
- 移动完成触发 `movement.arrived` 事件
- 移动被阻挡触发 `movement.blocked` 事件
- 同一实体同一时刻只能有一个移动请求

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_path_length | 500 | 是 | 单次路径搜索最大格子数，超限返回失败 |
| pathfinding_timeout_ms | 20 | 是 | 单次路径搜索超时 |
| max_concurrent_movements | 10,000 | 是 | 全局并发移动数上限 |
| pathfinding_algorithm | a_star | 是 | 寻路算法：a_star/dijkstra/jps/bfs |
| movement_tick_interval_ms | 100 | 是 | 移动tick粒度（位置更新频率） |
| max_formation_size | 50 | 是 | 编队最大成员数 |
| teleport_cooldown_precision_seconds | 1 | 是 | 传送冷却时间精度 |

## 与其他核心模块的关系

- **依赖**：
  - 地图系统（L0层）——移动需要地图的格子坐标、地形、通行性规则来计算路径和消耗。
  - 实体系统（L0层）——移动的主体是实体，移动力来自实体属性（如speed）。
- **被依赖**：
  - 战斗系统（L2层）——战斗的前置条件通常是移动到接战范围（如行军至敌方城池）。
  - 经济系统（L1层）——采集、贸易需要移动到资源点或交易点。
- **层级定位**：L1层业务核心模块，建立在地图与实体之上，是战斗与探索的前置条件。
