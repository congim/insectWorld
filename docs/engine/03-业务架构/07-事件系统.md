# 业务架构 · 事件系统 

> 管理游戏世界中的动态事件——天气变化、天灾、随机事件、定时事件，为SLG世界注入动态性和不可预测性。

---

## 核心模块定义

**是什么**：管理游戏世界中的动态事件——天气变化、天灾、随机事件、定时事件。事件系统负责事件的触发、执行和效果应用，是SLG世界动态性的来源。

**为什么是核心模块**：SLG是长线运营游戏，静态世界会让玩家疲劳。事件系统通过周期性/随机性事件为世界注入变化——季节性天气影响行军、随机天灾改变地形、定时事件提供限时玩法。框架提供事件的触发和执行机制，具体事件内容由内容配置定义。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| event_types | 事件类型定义 | 类型ID→{数据Schema, 发布者约束, 订阅者约束}映射 |
| event_filters | 事件过滤器 | 过滤器ID→{过滤条件, 目标订阅者}映射 |
| event_transformers | 事件转换器 | 转换器ID→{源事件, 转换逻辑, 目标事件}映射 |
| event_priority_rules | 事件优先级 | 规则列表，决定同类型事件的处理顺序 |
| event_history_rules | 事件历史 | 规则列表，决定哪些事件需要记录历史 |

## 扩展点契约

###  event.event_types

| 字段 | 值 |
|------|---|
| extension_point_id | event.event_types |
| core_module | 事件系统 |
| purpose | 定义自定义事件类型 |

| output_contract | `{ "type": "null", "description": "注册成功无返回值" }` |

## 框架默认行为

- 默认事件分发：同步顺序分发
- 默认无过滤器
- 默认无转换器
- 默认优先级：按订阅顺序
- 默认不记录事件历史
- 框架内置事件类型见第五章5.3节

## 约束

- 事件处理器内不可同步发布同类事件（防止递归风暴）
- 事件数据不可变（发布后不可修改）
- 事件处理器执行失败不影响后续处理器
- 事件分发有超时保护

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_custom_event_types | 100 | 是 | 自定义事件类型数上限 |
| max_event_filters | 50 | 是 | 事件过滤器数上限 |
| max_event_transformers | 20 | 是 | 事件转换器数上限 |
| event_history_max_records | 10,000 | 是 | 事件历史最大记录数 |
| event_history_retention_days | 7 | 是 | 事件历史保留天数 |
| scheduled_event_precision_seconds | 1 | 是 | 定时事件触发精度 |
| max_concurrent_active_events | 50 | 是 | 同时活跃的动态事件数上限（如同时多种天气） |
| event_effect_timeout_seconds | 60 | 是 | 单事件效果执行超时 |

## 与其他核心模块的关系

- **依赖**：
  - 规则系统（L3层）——规则系统的触发和动作通过事件系统分发；事件优先级、过滤、转换可由规则系统配置。
  - Buff系统（L2层）——Buff的挂载/移除/触发依赖事件系统（如 `combat.damage_received` 触发反击Buff）；Buff事件通过事件总线传播。
- **被依赖**：无（顶层业务核心模块）。事件系统为游戏世界注入动态性，不被其他业务核心模块依赖。
- **层级定位**：L3层顶层业务核心模块，统筹游戏世界的动态事件调度。
