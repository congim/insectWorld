# 业务架构 · 经济系统 

> 管理资源的生产、采集、交易、消耗和转换——从蚂蚁采集食物到星际贸易，资源流转的底层动力。

---

## 核心模块定义

**是什么**：管理资源的生产、采集、交易、消耗和转换——从蚂蚁采集食物到星际贸易。

**为什么是核心模块**：每个SLG都有经济循环。资源是驱动玩家行为的底层动力，经济系统管理的是"资源如何流转"的机制，具体资源类型和公式由内容配置定义。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| resource_types | 资源类型定义 | 类型ID→{名称, 上限, 显示优先级}映射 |
| production_rules | 生产规则 | 规则ID→{产出者类型, 产出公式, 产出间隔}映射 |
| collection_rules | 采集规则 | 规则ID→{采集者类型, 目标类型, 产出公式}映射 |
| trade_rules | 交易规则 | 规则ID→{交易类型, 汇率公式, 手续费}映射 |
| consumption_rules | 消耗规则 | 规则ID→{消耗者类型, 消耗公式, 消耗触发}映射 |
| conversion_rules | 转换规则 | 规则ID→{输入资源, 输出资源, 转换公式}映射 |
| storage_rules | 仓储规则 | 规则ID→{仓储类型, 上限公式, 溢出处理}映射 |
| economy_modifiers | 经济修正 | 修正器ID→{条件, 产出/消耗倍率}映射 |

## 框架默认行为

- 默认资源类型：无（必须由内容配置定义）
- 默认生产间隔：每游戏小时
- 默认无交易
- 默认无转换
- 默认仓储无上限
- 资源变更触发 `economy.resource_changed` 事件
- 资源不足时消耗操作失败

## 约束

- 资源值不可为负数
- 资源变更必须通过经济系统（不可直接修改实体属性）
- 交易双方必须同时满足交易条件
- 生产/采集/消耗操作是原子性的

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_resource_types | 30 | 是 | 资源类型数量上限 |
| max_resource_amount | 2,147,483,647 | 是 | 单资源持有量上限（int32最大值） |
| production_tick_interval_seconds | 60 | 是 | 生产tick间隔 |
| max_production_rules | 200 | 是 | 生产规则数量上限 |
| trade_timeout_seconds | 10 | 是 | 交易操作超时 |
| max_trade_partners | 100 | 是 | 单玩家最大交易伙伴数 |
| resource_overflow_strategy | clamp | 是 | 溢出处理：clamp/discard/convert |
| economy_audit_retention_days | 30 | 是 | 经济操作审计日志保留天数 |

## 与其他核心模块的关系

- **依赖**：
  - 实体系统（L0层）——生产者、采集者、消费者都是实体；产出/消耗公式引用实体属性。
  - Buff系统（L2层）——经济修正器（如科技加成、联盟光环）通过Buff机制作用于产出/消耗倍率。
- **被依赖**：
  - 联盟系统（L3层）——联盟福利、升级消耗依赖经济系统提供资源操作；联盟加成通过economy_modifiers作用。
  - 赛季系统（L3层）——赛季重置时保留部分资源（如高级货币），赛季积分可来源于经济指标。
- **层级定位**：L1层业务核心模块，是驱动玩家行为的底层动力。
