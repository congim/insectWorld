# 业务架构 · 赛季系统 

> 管理游戏的时间大循环——赛季阶段定义、阶段转换、赛季重置、跨赛季数据继承，长线运营的核心节奏。

---

## 核心模块定义

**是什么**：管理游戏的时间大循环——赛季阶段定义、阶段转换、赛季重置、跨赛季数据继承。

**为什么是核心模块**：现代SLG几乎都有赛季机制。赛季是长线运营的核心节奏，框架提供赛季的状态机和阶段管理，具体阶段定义和重置规则由内容配置定义。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| season_phases | 赛季阶段定义 | 阶段ID→{名称, 持续时间, 转换条件, 阶段效果}映射 |
| season_transition_rules | 阶段转换规则 | 规则ID→{源阶段, 目标阶段, 条件, 延迟}映射 |
| season_reset_rules | 重置规则 | 规则ID→{重置范围, 保留列表, 重置动作}映射 |
| season_inherit_rules | 继承规则 | 规则ID→{继承数据, 继承条件, 继承公式}映射 |
| season_rewards | 赛季奖励 | 奖励ID→{条件, 奖励内容}映射 |
| season_events | 赛季事件 | 事件ID→{触发阶段, 条件, 效果}映射 |
| season_scoring_rules | 积分规则 | 规则ID→{积分来源, 积分公式, 积分用途}映射 |

## 框架默认行为

- 默认阶段：准备期→发展期→争霸期→结算期
- 默认转换条件：时间到期
- 默认重置：重置地图和实体，保留玩家账号和部分资源
- 默认继承：玩家等级、英雄、科技
- 阶段转换触发 `season.phase_changed` 事件
- 赛季结束触发 `season.ended` 事件
- 赛季开始触发 `season.started` 事件

## 约束

- 赛季阶段必须形成有向无环图（DAG），不可循环
- 阶段转换是单向的（不可回退到前一阶段）
- 重置操作不可撤销
- 继承数据在重置前快照，重置后按继承规则写入

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_season_phases | 10 | 是 | 赛季阶段数上限 |
| max_season_duration_days | 120 | 是 | 单赛季最大持续天数 |
| season_reset_timeout_seconds | 300 | 是 | 赛季重置操作超时 |
| max_inherit_rules | 50 | 是 | 继承规则数量上限 |
| reward_distribution_batch_size | 100 | 是 | 奖励发放批量大小（分批避免峰值） |
| reward_distribution_timeout_seconds | 600 | 是 | 奖励发放总超时 |
| max_scoring_rules | 20 | 是 | 积分规则数量上限 |
| season_snapshot_required | true | 是 | 是否强制要求赛季快照 |

## 与其他核心模块的关系

- **依赖**：
  - 规则系统（L3层）——阶段转换条件、重置触发、积分计算均通过规则系统配置和执行。
  - 经济系统（L1层）——赛季重置时保留/重置资源依赖经济系统的资源类型定义；赛季奖励发放通过经济系统。
- **被依赖**：无（顶层业务核心模块）。赛季系统是长线运营的顶层节奏控制器，不被其他业务核心模块依赖。
- **层级定位**：L3层顶层业务核心模块，统筹全局时间节奏与跨赛季数据生命周期。
