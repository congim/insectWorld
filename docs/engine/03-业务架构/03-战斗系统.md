# 业务架构 · 战斗系统 

> 编排战斗的完整流程——从接战判定到战报生成，包括伤害计算管线、克制应用、技能释放顺序。

---

## 核心模块定义

**是什么**：编排战斗的完整流程——从接战判定到战报生成，包括伤害计算管线、克制应用、技能释放顺序。

**为什么是核心模块**：每个SLG都有战斗。无论回合制、实时制还是自动演算，都需要战斗流程编排。战斗系统是SLG的核心体验，框架提供的是"流程框架"，具体公式和效果由内容配置注入。

**配置注入方式**：

| 扩展点 | 用途 | 契约摘要 |
|-----------|------|---------|
| combat_types | 战斗类型定义 | 类型ID→{流程模板, 参与者约束}映射 |
| combat_phases | 战斗阶段定义 | 阶段ID→{顺序, 持续方式, 可执行动作}映射 |
| damage_formulas | 伤害公式 | 公式ID→{表达式, 变量列表}映射 |
| counter_matrix | 克制矩阵 | {攻击方标签, 防御方标签}→倍率映射 |
| combat_skills | 战斗技能 | 技能ID→{触发条件, 效果列表, 冷却}映射 |
| combat_formation_effects | 阵型效果 | 阵型ID→{条件, 属性修正}映射 |
| combat_result_modifiers | 战果修正 | 修正器ID→{条件, 修正效果}映射 |
| combat_loot_rules | 战利品规则 | 规则列表，决定战胜后获得什么 |

## 框架默认行为

- 默认自动演算战斗（SLG最常见）
- 默认战斗阶段：接战→先手判定→轮次循环→结算
- 默认伤害公式：`atk * counter_multiplier - def`
- 默认无克制（所有倍率=1.0）
- 默认无技能
- 默认无阵型效果
- 默认战报包含：双方阵容、每轮伤害、最终结果

## 约束

- 战斗一旦开始不可中途取消（可配置撤退条件）
- 战斗结果由框架计算，内容配置不可覆盖
- 战斗结束触发 `combat.ended` 事件
- 同一实体同一时刻只能参与一场战斗
- 战斗中的实体不可移动

### 边界条件

| 参数 | 默认值 | 可配 | 说明 |
|------|--------|------|------|
| max_combat_participants | 50 | 是 | 单场战斗最大参与者数 |
| max_combat_rounds | 30 | 是 | 单场战斗最大轮数，超限强制结束按平局处理 |
| combat_timeout_seconds | 30 | 是 | 单场战斗总超时 |
| max_concurrent_combats | 1,000 | 是 | 全局并发战斗数上限 |
| damage_calculation_timeout_ms | 10 | 是 | 单次伤害计算超时 |
| max_skills_per_combatant | 10 | 是 | 单参战者最大技能数 |
| combat_report_size_kb | 64 | 是 | 战报大小上限 |
| max_loot_items | 20 | 是 | 单场战斗最大战利品条目数 |

## 与其他核心模块的关系

- **依赖**：
  - 移动系统（L1层）——战斗的前置通常是移动到接战范围；战斗中实体不可移动（状态锁定）。
  - 实体系统（L0层）——战斗的参与者是实体，伤害公式引用实体属性（atk/def/hp）。
  - Buff系统（L2层）——战斗中的技能效果、阵型加成、地形加成通过Buff机制作用于实体属性。
- **被依赖**：
  - 联盟系统（L3层）——联盟外交状态（敌对/同盟）决定能否开战，战斗结果影响联盟关系。
  - 赛季系统（L3层）——战斗结果是赛季积分的重要来源，赛季阶段可能限制PVP战斗。
- **层级定位**：L2层核心业务核心模块，是SLG的核心体验所在。
