# 项目长期约定

## 协作模式（2026-08-11更新）
- **用户授权主理人自主决策**："不要来找我了，你自己做最优的决定"——ADR冻结、实现排期、代码落地等执行决策由主理人自行拍板，不再逐项征求确认；只在里程碑/质量门处汇报结果
- 开发计划：《通用SLG服务端开发计划.md》为执行依据（P1切片→P2架构→P3六骨头→P4存量+题材）

## 架构目标边界（2026-08-10确认）
- **通用 = SLG品类共性机制**（用户体系、建筑、采集等每个SLG都一样的系统）
- **特殊业务玩法 = 另行扩展开发**（每个游戏有自己的特殊性）
- **目标 = 基础打牢、拓展改动方便**（非"所有玩法零代码修改"）

## 三项决策（2026-08-11确认）
- 邮件：后置（先扩展开发，跑通一个题材后再评估是否提升为骨头）
- 任务/成就：走配置化（规则系统实例化复用，不新增骨头）
- 聊天：留拓展（不进框架，补接入规范即可）

## 分层架构模型
- L0 基础设施层（共享内核：eventbus/config/entity/persist）
- L1 SLG共性机制层（server/framework/，21根骨头，零题材字符串）
- L2 题材内容层（18个配置文件，肉）
- L3 题材特殊扩展层（server/extensions/<题材>/，独立go.mod）
- 依赖方向：L0 ← L1 ← L2 ← L3

## 工程改造核心
- 行为注册表：action_registry.go（RuleActionHandler接口+Register），新动作=题材层init()注册，框架零改动
- 规则引擎执行动作从写死枚举改为注册表查表分发
- 启动时全量校验"配置引用的type均已注册，否则拒绝启动"

## 第一轮打牢基础优先级（P0，6项）
1. 玩家档案
2. 建筑升级流程
3. 采集队调度
4. 背包/道具
5. 兵种训练队列
6. 个人科技研究
