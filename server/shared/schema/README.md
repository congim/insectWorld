# 数据库结构

当前处于可丢弃数据的开发阶段，`baseline/` 是唯一可执行数据库基线。文件名前缀同时定义执行顺序和数据所有者：

| 顺序 | 文件 | 写入所有者 | 当前用途 |
|---|---|---|---|
| 00 | `00_kernel.sql` | 通用内核 | Outbox租约投递 |
| 10 | `10_identity.sql` | Identity | 账号与认证审计 |
| 20 | `20_growth.sql` | Growth | 玩家档案、建筑、训练、单位名册 |
| 30 | `30_economy.sql` | Economy | 字符串资源账户与幂等操作账本 |
| 40 | `40_config.sql` | Config | 配置版本与配置审计 |
| 50 | `50_persist.sql` | Persist | 迁移记录、快照、归档和备份任务 |

基线只包含当前已有仓储实现或运行时调用方的表。Combat、World、Social、Match等尚未落地的持久化模型，不通过预留空表或表名常量提前冻结；它们应在首个真实仓储与验收测试同时加入。

## 本地重建与测试

本地测试数据库固定使用安全隔离名称 `insect_world_test`。执行：

```bash
./scripts/reset_local_mysql.sh
./scripts/test_local_mysql.sh
```

重建脚本只允许删除以 `_test` 结尾的数据库，并按文件名前缀顺序执行全部基线。连接默认值和覆盖变量以根目录 `AGENTS.md` 为准；密码不会输出到日志。

## 变更阶段

基线冻结前，字段和索引直接修改所属基线文件并重建测试库，不增加 `ALTER TABLE` 补丁。进入共享环境或产生不可丢弃数据后，从冻结点开始启用 `migrations/`，并按扩展、回填、切换、清理拆分前向兼容迁移，禁止改写已执行版本。

所有索引随表定义维护，不再设置独立 `indexes/`；游戏内容来自游戏包，不再维护固定资源枚举或假路由种子数据。
